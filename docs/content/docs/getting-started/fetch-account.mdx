在本系列的前一篇文章中，我们学习了如何发送一个创建新的 Solana token 的交易，也称为 `Mint` 账户。在最后一篇文章中，我们将学习如何检索我们创建的账户并访问其解码后的数据。

## 使用 RPC 方法获取

可以使用 `getAccountInfo` 或 `getMultipleAccounts` 等 RPC 方法从链上地址获取账户。这些方法接受各种选项，并根据这些选项返回不同的输出。例如，`encoding` 选项将决定在返回账户的编码数据时使用哪种字符串格式。

```ts twoslash
import { Rpc, SolanaRpcApi } from "@solana/kit";
const rpc = null as unknown as Rpc<SolanaRpcApi>;
// ---cut-before---
import { address } from "@solana/kit";

const { value: account } = await rpc.getAccountInfo(address("1234..5678")).send();
const { value: accounts } = await rpc.getMultipleAccounts([address("1234..5678")]).send();
```

## 使用助手函数获取

拥有如此多的可能返回值使得处理检索到的信息变得更加困难。例如，`getAccountInfo` RPC 方法将默认为 Base58 编码，而 `getMultipleAccounts` 方法将默认为 Base64。

此外，当尝试获取链上不存在的账户时，将返回 `null` 值，这在处理多个账户时尤其不方便，因为它需要将地址数组与账户数组压缩在一起以确定哪些账户缺失。

因此，Kit 提供了一组类型和助手函数，旨在统一这些 API 并使它们更易于使用。例如，`fetchEncodedAccount` 和 `fetchEncodedAccounts` 助手函数可用于获取一个或多个账户，并以统一的格式返回它们。

```ts twoslash
import { Rpc, SolanaRpcApi } from "@solana/kit";
const rpc = null as unknown as Rpc<SolanaRpcApi>;
// ---cut-before---
import { address, fetchEncodedAccount, fetchEncodedAccounts, MaybeEncodedAccount } from "@solana/kit";

const account = await fetchEncodedAccount(rpc, address("1234..5678"));
const accounts = await fetchEncodedAccounts(rpc, [address("1234..5678")]);

account satisfies MaybeEncodedAccount;
accounts satisfies MaybeEncodedAccount[];
```

正如你所看到的，返回类型都是 `MaybeAccounts`。这意味着该账户可能存在于链上，也可能不存在。它包含一个 `exists` 字段，指示该账户是否存在。如果存在，我们可以访问其所有字段。否则，我们只知道它的地址 —— 因为它是作为输入提供的。

```ts twoslash
import { Rpc, SolanaRpcApi } from "@solana/kit";
const rpc = null as unknown as Rpc<SolanaRpcApi>;
// ---cut-before---
import { EncodedAccount, address, Address, fetchEncodedAccount, fetchEncodedAccounts } from "@solana/kit";

const account = await fetchEncodedAccount(rpc, address("1234..5678"));

if (account.exists) {
  // 如果它存在，我们可以访问它的所有字段。
  account satisfies EncodedAccount<"1234..5678">;
} else {
  // 否则，我们只知道它的地址。
  account satisfies { address: Address<"1234..5678">; exists: false };
}
```

我们还可以使用 `assertAccountExists` 助手函数来断言账户的存在。如果账户不存在，这将抛出一个错误，并告诉 TypeScript 我们的 `MaybeAccount` 实际上是一个 `Account`。

```ts twoslash
import { Rpc, SolanaRpcApi } from "@solana/kit";
const rpc = null as unknown as Rpc<SolanaRpcApi>;
// ---cut-before---
import { assertAccountExists, EncodedAccount, address, fetchEncodedAccount, fetchEncodedAccounts } from "@solana/kit";

const account = await fetchEncodedAccount(rpc, address("1234..5678"));
assertAccountExists(account);

account satisfies EncodedAccount;
```

## 手动解码数据

到目前为止，我们一直在处理编码的账户，这意味着获取的账户的 `data` 字段是一个字节数组 —— 即一个 `Uint8Array`。但实际上我们需要将该数据解码为更易于使用的格式。

Kit 提供了一组名为 Codecs 的序列化库。这些库提供类型和函数来创建 Codec 对象，这些对象可以组合在一起以创建更复杂的序列化和反序列化逻辑。

你可以在[此处阅读有关 Codecs 的更多信息](/docs/concepts/codecs)，但让我们快速了解如何创建一个 Codec 对象来解码我们的 `Mint` 账户。

Mint 账户由以下数据组成：

- `mintAuthority` 是一个可选地址。设置后，此地址可以铸造新的 token。
- `supply` 是一个使用 `u64` 的整数。这用于跟踪 token 的总供应量。
- `decimals` 是一个使用 `u8` 的整数。这用于跟踪 token 的小数位数。
- `isInitialized` 是一个使用单个字节的布尔值。这告诉我们 mint 账户是否已初始化。
- `freezeAuthority` 是一个可选地址。设置后，此地址可以冻结 token 账户。

通过组合各种 Codec 函数 —— 例如使用 `getStructCodec` 创建对象或使用 `getOptionCodec` 创建可选数据 —— 我们可以设计一个 Codec 对象来描述 `Mint` 账户的字节布局。这是一个说明该情况的例子。请注意，为了这个例子，`Mint` 账户的布局被稍微简化了。

```ts twoslash
import { Rpc, SolanaRpcApi } from "@solana/kit";
const rpc = null as unknown as Rpc<SolanaRpcApi>;
// ---cut-before---
import {
  address,
  Address,
  assertAccountExists,
  fetchEncodedAccount,
  getAddressCodec,
  getBooleanCodec,
  getOptionCodec,
  getStructCodec,
  getU64Codec,
  getU8Codec,
  Option,
} from "@solana/kit";

const account = await fetchEncodedAccount(rpc, address("1234..5678"));
assertAccountExists(account);

const mintCodec = getStructCodec([
  ["mintAuthority", getOptionCodec(getAddressCodec())], // [simplified]
  ["supply", getU64Codec()],
  ["decimals", getU8Codec()],
  ["isInitialized", getBooleanCodec()],
  ["freezeAuthority", getOptionCodec(getAddressCodec())], // [simplified]
]);

const decodedData = mintCodec.decode(account.data);
decodedData satisfies {
  mintAuthority: Option<Address>;
  supply: bigint;
  decimals: number;
  isInitialized: boolean;
  freezeAuthority: Option<Address>;
};
```

## 使用程序客户端解码

幸运的是，我们通常不需要手动创建这些 Codec 对象，因为程序客户端会为我们提供它们。这些助手函数通常是[通过 Codama IDL 生成的](https://github.com/codama-idl/codama)，并遵循 `getXCodec` 命名约定，其中 `X` 是账户的名称。

例如，我们可以从 `@solana-program/token` 库访问 `Mint` codec，如下所示。

```ts twoslash
import { Rpc, SolanaRpcApi } from "@solana/kit";
const rpc = null as unknown as Rpc<SolanaRpcApi>;
// ---cut-before---
import { address, assertAccountExists, fetchEncodedAccount } from "@solana/kit";
import { getMintCodec, Mint } from "@solana-program/token";

const account = await fetchEncodedAccount(rpc, address("1234..5678"));
assertAccountExists(account);

const mintCodec = getMintCodec();
const decodedData = mintCodec.decode(account.data);
decodedData satisfies Mint;
```

通过使用程序客户端的 `decodeX` 助手函数，可以进一步简化此过程。这些助手函数接受一个 `EncodedAccount` 或一个 `MaybeEncodedAccount`，并分别返回一个 `Account<T>` 或一个 `MaybeAccount<T>`，其中 `T` 是账户数据的类型。

```ts twoslash
import { Rpc, SolanaRpcApi } from "@solana/kit";
const rpc = null as unknown as Rpc<SolanaRpcApi>;
// ---cut-before---
import { Account, address, assertAccountExists, fetchEncodedAccount } from "@solana/kit";
import { decodeMint, Mint } from "@solana-program/token";

const account = decodeMint(await fetchEncodedAccount(rpc, address("1234..5678")));
assertAccountExists(account);
account satisfies Account<Mint>;
```

## 使用程序客户端获取和解码

最后但并非最不重要的一点是，可以使用程序客户端的 `fetchX` 助手函数一步完成账户的获取和解码。这些助手函数接受一个 `Rpc` 对象和一个 `Address`，并返回一个 `Account<T>`，其中 `T` 是账户数据的类型。这些助手函数还将断言账户的存在，如果账户不存在，则抛出错误。

这意味着，到目前为止我们所做的一切都可以简化为一行代码。

```ts twoslash
import { Rpc, SolanaRpcApi } from "@solana/kit";
const rpc = null as unknown as Rpc<SolanaRpcApi>;
// ---cut-before---
import { Account, address } from "@solana/kit";
import { fetchMint, Mint } from "@solana-program/token";

const account = await fetchMint(rpc, address("1234..5678"));
account satisfies Account<Mint>;
```

## 更新 `index.ts`

现在我们知道了如何获取和解码链上账户，让我们更新我们的主 `tutorial` 函数来获取我们在上一篇文章中创建的 `Mint` 账户并显示其解码后的数据。

由于它的一些数据是可选的，我们将使用 `unwrapOption` 助手函数将 `Option<T>` 类型转换为 `T | null`，然后再显示它们。

```ts twoslash title="src/index.ts"
// @filename: create-mint.ts
import { Address } from "@solana/kit";
import { Client } from "./client";

  return "" as Address;

// @filename: index.ts
// ---cut-before---
import { unwrapOption } from "@solana/kit"; // [!code ++]
import { fetchMint } from "@solana-program/token"; // [!code ++]

import { createClient } from "./client";
import { createMint } from "./create-mint";

async function tutorial() {
  const client = await createClient();
  const mintAddress = await createMint(client, { decimals: 2 });
  const mintAccount = await fetchMint(client.rpc, mintAddress); // [!code ++]
  console.log(`Mint created: ${mintAddress}.`);
  console.log(`Mint lamports: ${mintAccount.lamports}.`); // [!code ++]
  console.log(`Mint authority: ${unwrapOption(mintAccount.data.mintAuthority)}.`); // [!code ++]
  console.log(`Mint decimals: ${mintAccount.data.decimals}.`); // [!code ++]
  console.log(`Mint supply: ${mintAccount.data.supply}.`); // [!code ++]
}
```
