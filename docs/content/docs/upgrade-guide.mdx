## 为什么要升级？

Kit（之前称为 Web3.js v2）是对 [Web3.js 库](https://github.com/solana-labs/solana-web3.js/) 的完全重写。它的设计目标是比其前身更具可组合性、可定制性和效率。其函数式设计使得整个库都可以进行 tree-shaking，从而大大减小你的 bundle 大小。它还利用了现代 JavaScript 的特性——如原生 Ed25519 密钥支持和用于大数值的 `bigint` ——从而产生更小的 bundle，更好的性能，最重要的是，减少了你的应用程序的攻击面。

<Spread>
  ![Tree-shaking illustration. The left side shows a bunch of imports from Web3.js all being bundled despite only a
  couple being used. The right side shows an equivalent set of imports for Kit but only the used functions are
  bundled.](./tree-shaking.svg)
</Spread>

与 Web3.js 不同，Kit 不依赖于 JavaScript 类或其他不可 tree-shake 的特性。这引出了我们的第一个关键区别。

## 我的 `Connection` 类在哪里？

在 Web3.js 中，`Connection` 类充当一个中心入口点，使得库的 API 更容易通过单个对象被发现。然而，这是有代价的：使用 `Connection` 类迫使你将它提供的每个方法都打包进来，即使你只使用其中的几个。因此，你的用户必须下载整个库，即使其中大部分都未被使用。

为了避免这种情况，**Kit 不包含像 `Connection` 这样的单一入口点类**。相反，它提供了一组函数，你可以根据需要导入和使用。两个关键函数替代了 `Connection` 类的大部分功能：`createSolanaRpc` 和 `createSolanaRpcSubscriptions`。

前者 `createSolanaRpc` 返回一个 `Rpc` 对象，用于向指定的 endpoint 发出 RPC 请求。[在此阅读更多关于 RPC 的信息](/docs/kit/docs/kit/docs/kit/docs/kit/docs/concepts/rpc)。

<Spread>
<div className="2xl:flex 2xl:*:flex-1 2xl:items-start 2xl:gap-4">

```ts title="Web3.js"
import { Connection, PublicKey } from "@solana/web3.js";

// 创建一个 `Connection` 对象。
const connection = new Connection("https://api.devnet.solana.com", {
  commitment: "confirmed",
});

// 发送 RPC 请求。
const wallet = new PublicKey("1234..5678");
const balance = await connection.getBalance(wallet);
```

```ts twoslash title="Kit"
import { address, createSolanaRpc } from "@solana/kit";

// 创建一个 RPC 代理对象。
const rpc = createSolanaRpc("https://api.devnet.solana.com");

// 发送 RPC 请求。
const wallet = address("1234..5678");
const { value: balance } = await rpc.getBalance(wallet).send();
```

</div>
</Spread>

后者 `createSolanaRpcSubscriptions` 返回一个 `RpcSubscriptions` 对象，它允许你订阅 Solana 网络上的事件。[在此阅读更多关于 RPC 订阅的信息](/docs/kit/docs/kit/docs/kit/docs/kit/docs/concepts/rpc-subscriptions)。

<Spread>
<div className="2xl:flex 2xl:*:flex-1 2xl:items-start 2xl:gap-4">

```ts title="Web3.js"
import { Connection, PublicKey } from "@solana/web3.js";

// 创建一个带有 WebSocket endpoint 的 `Connection` 对象。
const connection = new Connection("https://api.devnet.solana.com", {
  wsEndpoint: "wss://api.devnet.solana.com",
  commitment: "confirmed",
});

// 订阅 RPC 事件并监听通知。
const wallet = new PublicKey("1234..5678");
connection.onAccountChange(wallet, (accountInfo) => {
  console.log(accountInfo);
});
```

```ts twoslash title="Kit"
import { address, createSolanaRpcSubscriptions } from "@solana/kit";

// 创建一个 RPC 订阅代理对象。
const rpcSubscriptions = createSolanaRpcSubscriptions("wss://api.devnet.solana.com");

// 使用 `AbortController` 取消订阅。
const abortController = new AbortController();

// 订阅 RPC 事件。
const wallet = address("1234..5678");
const accountNotifications = await rpcSubscriptions
  .accountNotifications(wallet, { commitment: "confirmed" })
  .subscribe({ abortSignal: abortController.signal });

try {
  // 监听事件通知。
  for await (const accountInfo of accountNotifications) {
    console.log(accountInfo);
  }
} catch (e) {
  // 优雅地处理订阅断开。
}
```

</div>
</Spread>

请注意，虽然 `Rpc` 和 `RpcSubscriptions` 看起来像类，但它们实际上是 [`Proxy` 对象](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy)。这意味着它们基于方法名和参数动态地构造 RPC 请求或订阅。然后使用 TypeScript 为 RPC API 提供类型安全，使其易于发现可用的 RPC 方法，同时保持库的轻量级。无论你的 RPC 支持 1 个方法还是 100 个方法，bundle 大小都保持不变。

## 获取和解码账户

既然我们知道如何发送 RPC 请求，那么获取一个或多个链上账户就像调用适当的 RPC 方法一样简单。例如，以下是如何使用其地址检索账户：

<Spread>
<div className="2xl:flex 2xl:*:flex-1 2xl:items-start 2xl:gap-4">

```ts title="Web3.js"
import { PublicKey } from "@solana/web3.js";

const wallet = new PublicKey("1234..5678");
const account = await connection.getAccountInfo(wallet);
```

```ts twoslash title="Kit"
import { address } from "@solana/kit";
// ---cut-start---
import { createSolanaRpc } from "@solana/kit";
const rpc = createSolanaRpc("https://api.devnet.solana.com");
// ---cut-end---

const wallet = address("1234..5678");
const { value: account } = await rpc.getAccountInfo(wallet).send();
```

</div>
</Spread>

Kit 还提供了辅助函数，如 `fetchEncodedAccount` 和 `fetchEncodedAccounts`，它们返回 `MaybeAccount` 对象。这些对象存储账户的地址，并包含一个 `exists` 布尔值，用于指示该账户是否存在于链上。如果 `exists` 为 `true`，则该对象还包含预期的账户信息。这些辅助函数还统一了账户的返回类型，确保无论用于获取它们的编码如何，都保持一致性。

```ts twoslash title="Kit"
import { address, assertAccountExists, fetchEncodedAccount } from "@solana/kit";
// ---cut-start---
import { createSolanaRpc } from "@solana/kit";
const rpc = createSolanaRpc("https://api.devnet.solana.com");
// ---cut-end---

const wallet = address("1234..5678");
const account = await fetchEncodedAccount(rpc, wallet);
assertAccountExists(account);
account.data satisfies Uint8Array;
```

此外，Kit 引入了一个名为 `codecs` 的新序列化库。Codecs 是可组合的对象，用于将任何类型编码和解码为 `Uint8Array` 或从 `Uint8Array` 解码。例如，以下是如何通过组合多个 codec 原语来定义 `Person` 账户的 codec：

```ts twoslash title="Kit"
import {
  address,
  Address,
  addCodecSizePrefix,
  Codec,
  getAddressCodec,
  getStructCodec,
  getU32Codec,
  getU8Codec,
  getUtf8Codec,
} from "@solana/kit";

type Person = {
  age: number;
  discriminator: number;
  name: string;
  wallet: Address;
};

const personCodec: Codec<Person> = getStructCodec([
  ["discriminator", getU8Codec()], // A single-byte account discriminator.
  ["wallet", getAddressCodec()], // A 32-byte account address.
  ["age", getU8Codec()], // An 8-bit unsigned integer.
  ["name", addCodecSizePrefix(getUtf8Codec(), getU32Codec())], // A UTF-8 string with a 32-bit length prefix.
]);

const bytes = personCodec.encode({
  age: 42,
  discriminator: 0,
  name: "Alice",
  wallet: address("1234..5678"),
});
```

[你可以在这里阅读更多关于 codecs 的信息](/docs/kit/docs/kit/docs/kit/docs/kit/docs/concepts/codecs)。

一旦你有了账户数据的 codec，你就可以使用 `decodeAccount` 函数将编码的账户转换为解码的账户。

```ts twoslash title="Kit"
import { address, Codec, decodeAccount, fetchEncodedAccount } from "@solana/kit";
// ---cut-start---
import {
  Address,
  createSolanaRpc,
  addCodecSizePrefix,
  getAddressCodec,
  getStructCodec,
  getU32Codec,
  getU8Codec,
  getUtf8Codec,
} from "@solana/kit";
const rpc = createSolanaRpc("https://api.devnet.solana.com");
type Person = {
  age: number;
  discriminator: number;
  name: string;
  wallet: Address;
};
const personCodec: Codec<Person> = getStructCodec([
  ["discriminator", getU8Codec()],
  ["wallet", getAddressCodec()],
  ["age", getU8Codec()],
  ["name", addCodecSizePrefix(getUtf8Codec(), getU32Codec())],
]);
// ---cut-end---

const wallet = address("1234..5678");
const account = await fetchEncodedAccount(rpc, wallet);
const decodedAccount = decodeAccount(account, personCodec);

if (decodedAccount.exists) {
  decodedAccount.data satisfies Person;
}
```

## 使用程序库

幸运的是，你不需要每次解码账户时都创建一个自定义的 codec。Kit 为许多流行的 Solana 程序提供了客户端库，可以帮助你完成这项工作。例如，System program 辅助函数在 `@solana-program/system` 库中可用。

这些库是[通过 Codama 生成的](https://github.com/codama-idl/codama)，确保它们具有一致的结构。例如，来自 `@solana-program/system` 的 `fetchNonce` 函数可用于从其地址获取和解码 `Nonce` 账户。

```ts twoslash title="Kit"
import { Account, address } from "@solana/kit";
import { fetchNonce, Nonce } from "@solana-program/system";
// ---cut-start---
import { createSolanaRpc } from "@solana/kit";
const rpc = createSolanaRpc("https://api.devnet.solana.com");
// ---cut-end---

const account: Account<Nonce> = await fetchNonce(rpc, address("1234..5678"));
```

[查看“兼容客户端”页面](/docs/kit/docs/kit/docs/kit/docs/kit/docs/compatible-clients)以获取与 Kit 兼容的可用程序库的列表。

## 创建指令

除了获取和解码账户外，生成的程序客户端还提供用于创建指令的函数。这些函数遵循 `getXInstruction` 命名约定，其中 `X` 是指令的名称。

例如，以下是如何使用 Web3.js 中的 `SystemProgram` 类创建一个 `CreateAccount` 指令，以及使用 `@solana-program/system` 库的等效 Kit 代码。

<Spread>
<div className="2xl:flex 2xl:*:flex-1 2xl:items-start 2xl:gap-4">

```ts title="Web3.js"
import { PublicKey, SystemProgram } from "@solana/web3.js";

const transferSol = SystemProgram.transfer({
  fromPubkey: new PublicKey("2222..2222"),
  toPubkey: new PublicKey("3333..3333"),
  lamports: 1_000_000_000, // 1 SOL.
});
```

```ts twoslash title="Kit"
import { address, createNoopSigner } from "@solana/kit";
import { getTransferSolInstruction } from "@solana-program/system";

const transferSol = getTransferSolInstruction({
  source: createNoopSigner(address("2222..2222")),
  destination: address("3333..3333"),
  amount: 1_000_000_000, // 1 SOL.
});
```

</div>
</Spread>

<Callout title="Transaction signers">
  注意 Kit 示例中的 `createNoopSigner` 函数。与 Web3.js 不同，当账户需要充当指令的 signer 时，Kit 使用 `TransactionSigner` 对象。这允许从构建的交易中提取 signer，从而实现自动交易签名，而无需手动扫描指令以查找所需的 signer。我们将在下面的[“Signing transactions”部分](#signing-transactions)中进一步探讨这一点。
</Callout>

现在我们知道了如何创建指令，让我们看看如何使用它们来构建交易。

## 构建交易

Web3.js 在创建交易时做出了一些假设。例如，它默认为最新的交易版本，并使用最近的区块哈希作为交易的有效期。虽然这通过提供合理的默认值来改善开发者体验，但这是以 tree-shakeability 为代价的。如果应用程序仅依赖于持久 nonce 有效期，它仍然会被迫打包与区块哈希有效期相关的逻辑，即使它从未使用过。

另一方面，Kit 不对交易做任何假设。相反，它要求开发者使用一系列辅助函数显式地提供所有必要的信息。这些函数逐步将空交易消息转换为完全编译和签名的交易，准备发送到网络。这种方法确保了强大的类型安全性，允许辅助函数在编译时强制执行有效的交易状态。

由于 TypeScript 无法重新声明现有变量的类型，因此每个交易辅助函数都会返回一个新的不可变的交易对象，并更新了类型。为了简化这一点，Kit 提供了一个 `pipe` 函数，允许开发者有效地链接交易辅助函数。

<Spread>
<div className="2xl:flex 2xl:*:flex-1 2xl:items-start 2xl:gap-4">

```ts title="Web3.js"
import { PublicKey, SystemProgram, Transaction } from "@solana/web3.js";
import { createInitializeMintInstruction } from "@solana/spl-token";

const latestBlockhash = await connection.getLatestBlockhash();
const createAccount = SystemProgram.createAccount(createAccountInput);
const initializeMint = createInitializeMintInstruction(initializeMintInput);

const transaction = new Transaction({ feePayer, ...latestBlockhash }).add(createAccount).add(initializeMint);
```

```ts twoslash title="Kit"
import {
  appendTransactionMessageInstructions,
  createTransactionMessage,
  pipe,
  setTransactionMessageFeePayerSigner,
  setTransactionMessageLifetimeUsingBlockhash,
} from "@solana/kit";
import { getCreateAccountInstruction } from "@solana-program/system";
import { getInitializeMintInstruction } from "@solana-program/token";
// ---cut-start---
import { createSolanaRpc, TransactionSigner } from "@solana/kit";
const rpc = createSolanaRpc("https://api.devnet.solana.com");
const payer = null as unknown as TransactionSigner;
const createAccountInput = null as unknown as Parameters<typeof getCreateAccountInstruction>[0];
const initializeMintInput = null as unknown as Parameters<typeof getInitializeMintInstruction>[0];
// ---cut-end---

const { value: latestBlockhash } = await rpc.getLatestBlockhash().send();
const createAccount = getCreateAccountInstruction(createAccountInput);
const initializeMint = getInitializeMintInstruction(initializeMintInput);

const transactionMessage = pipe(
  createTransactionMessage({ version: 0 }),
  (tx) => setTransactionMessageFeePayerSigner(payer, tx),
  (tx) => setTransactionMessageLifetimeUsingBlockhash(latestBlockhash, tx),
  (tx) => appendTransactionMessageInstructions([createAccount, initializeMint], tx),
);
```

</div>
</Spread>

## 签署交易

Web3.js 和 Kit 都允许 keypair 签署或部分签署交易。然而，Kit 利用原生 [`CryptoKeyPair`](https://developer.mozilla.org/en-US/docs/Web/API/CryptoKeyPair) API 安全地生成和导出 keypair，而不会将私钥暴露给环境。

<Spread>
<div className="2xl:flex 2xl:*:flex-1 2xl:items-start 2xl:gap-4">

```ts title="Web3.js"
import { Keypair, Transaction } from "@solana/web3.js";

const payer = Keypair.generate();
const authority = Keypair.generate();

transaction.sign([payer, authority]);
```

```ts twoslash title="Kit"
import { compileTransaction, generateKeyPair, signTransaction } from "@solana/kit";
// ---cut-start---
import { CompilableTransactionMessage, TransactionMessageWithBlockhashLifetime } from "@solana/kit";
const transactionMessage = null as unknown as CompilableTransactionMessage & TransactionMessageWithBlockhashLifetime;
// ---cut-end---

const [payer, authority] = await Promise.all([generateKeyPair(), generateKeyPair()]);

const transaction = compileTransaction(transactionMessage);
const signedTransaction = await signTransaction([payer, authority], transaction);
```

</div>
</Spread>

此外，如[“创建指令”](#creating-instructions)部分所述，Kit 引入了 **signer 对象**。这些对象处理交易和消息签名，同时抽象出底层的签名机制。这可以是使用 Crypto KeyPair、浏览器中的 wallet adapter、Noop signer 或我们想要的任何东西。以下是一些如何创建 signer 的示例：

```ts twoslash title="Kit"
import { address, createNoopSigner, generateKeyPairSigner } from "@solana/kit";
import { useWalletAccountTransactionSendingSigner } from "@solana/react";
// ---cut-start---
const account = null as unknown as Parameters<typeof useWalletAccountTransactionSendingSigner>[0];
const currentChain = null as unknown as Parameters<typeof useWalletAccountTransactionSendingSigner>[1];
// ---cut-end---

// 使用 CryptoKeyPairs。
const myKeypairSigner = await generateKeyPairSigner();

// 使用 wallet 标准。
const myWalletSigner = useWalletAccountTransactionSendingSigner(account, currentChain);

// 使用 Noop signer。
const myNoopSigner = createNoopSigner(address("1234..5678"));
```

使用 signer 的一个关键优势是，可以在创建指令时直接传递它们。这使得交易消息能够感知所需的 signer，从而无需手动跟踪它们。在这种情况下，可以使用 `signTransactionMessageWithSigners` 函数来使用所有附加的 signer 签署交易。

以下是将 signer 传递给指令和交易 fee payer 的示例。请注意，`signTransactionMessageWithSigners` 不需要传入额外的 signer - 它已经知道需要哪些 signer。

```ts twoslash title="Kit"
import { signTransactionMessageWithSigners } from "@solana/kit";
import { getCreateAccountInstruction } from "@solana-program/system";
import { getInitializeMintInstruction, TOKEN_PROGRAM_ADDRESS } from "@solana-program/token";
// ---cut-start---
import {
  address,
  appendTransactionMessageInstructions,
  createTransactionMessage,
  generateKeyPairSigner,
  pipe,
  setTransactionMessageFeePayerSigner,
  setTransactionMessageLifetimeUsingBlockhash,
} from "@solana/kit";
const latestBlockhash = null as unknown as Parameters<typeof setTransactionMessageLifetimeUsingBlockhash>[0];
const space = null as unknown as Parameters<typeof getCreateAccountInstruction>[0]["space"];
const lamports = null as unknown as Parameters<typeof getCreateAccountInstruction>[0]["lamports"];
// ---cut-end---

// 创建 signer。
const [payer, mint] = await Promise.all([generateKeyPairSigner(), generateKeyPairSigner()]);

// 创建指令。
const createAccount = getCreateAccountInstruction({
  payer, // <- TransactionSigner // [!code highlight]
  newAccount: mint, // <- TransactionSigner // [!code highlight]
  space,
  lamports,
  programAddress: TOKEN_PROGRAM_ADDRESS,
});
const initializeMint = getInitializeMintInstruction({
  mint: mint.address,
  mintAuthority: address("1234..5678"),
  decimals: 2,
});

// 创建交易。
const transactionMessage = pipe(
  createTransactionMessage({ version: 0 }),
  (tx) => setTransactionMessageFeePayerSigner(payer, tx), // <- TransactionSigner // [!code highlight]
  (tx) => setTransactionMessageLifetimeUsingBlockhash(latestBlockhash, tx),
  (tx) => appendTransactionMessageInstructions([createAccount, initializeMint], tx),
);

// 签署交易。
const signedTransaction = await signTransactionMessageWithSigners(transactionMessage);
```

[在此阅读更多关于 signer 的信息](/docs/kit/docs/kit/docs/kit/docs/kit/docs/concepts/signers)。

## 发送和确认交易

最后，我们可以将已签名的交易发送到网络并等待确认。虽然有多种确认交易的方式（例如，轮询、监听事件等），但 Web3.js 和 Kit 都提供了一种适用于大多数用例的默认策略。

<Spread>
<div className="2xl:flex 2xl:*:flex-1 2xl:items-start 2xl:gap-4">

```ts title="Web3.js"
import { Keypair, sendAndConfirmTransaction } from "@solana/web3.js";

// 创建 keypair。
const payer = Keypair.generate();
const mint = Keypair.generate();

// 签名、发送并确认交易。
const transactionSignature = await sendAndConfirmTransaction(connection, transaction, [feePayer, mint]);
```

```ts twoslash title="Kit"
import { sendAndConfirmTransactionFactory, getSignatureFromTransaction } from "@solana/kit";
// ---cut-start---
import {
  createSolanaRpc,
  createSolanaRpcSubscriptions,
  FullySignedTransaction,
  TransactionWithBlockhashLifetime,
} from "@solana/kit";
const rpc = createSolanaRpc("https://api.devnet.solana.com");
const rpcSubscriptions = createSolanaRpcSubscriptions("wss://api.devnet.solana.com");
const signedTransaction = null as unknown as FullySignedTransaction & TransactionWithBlockhashLifetime;
// ---cut-end---

// 从你的 RPC 和 RPC 订阅对象创建一个发送和确认函数。
const sendAndConfirm = sendAndConfirmTransactionFactory({ rpc, rpcSubscriptions });

// 使用它来发送和确认任何已签名的交易。
const transactionSignature = getSignatureFromTransaction(signedTransaction);
await sendAndConfirm(signedTransaction, { commitment: "confirmed" });
```

</div>
</Spread>

请注意，`sendAndConfirm` 函数不会返回交易签名。这是因为交易签名在发送之前是确定性已知的。为了访问它，Kit 提供了一个单独的 `getSignatureFromTransaction` 辅助函数，如上面的代码片段所示。

此外，`sendAndConfirmTransactionFactory` 函数需要一个 RPC 和一个 RPC 订阅对象。但是，这并不意味着需要完整的 RPC 和 RPC 订阅实现。只需要实现以下 API 方法：

- 对于 `Rpc` 对象：`GetEpochInfoApi`、`GetSignatureStatusesApi` 和 `SendTransactionApi`。
- 对于 `RpcSubscriptions` 对象：`SignatureNotificationsApi` 和 `SlotNotificationsApi`。

## 结束语

我们现在已经探讨了 Web3.js 和 Kit 之间的主要区别，为你升级项目奠定了坚实的基础。由于 Kit 是完全重写的，因此没有简单的逐步迁移指南，并且该过程可能需要一些时间。

为了 облегчить перехета，Kit 提供了一个 `@solana/compat` 包，该包允许增量迁移。此包包含在 Web3.js 和 Kit 之间转换核心类型（例如公钥和交易）的函数。这意味着你可以开始集成 Kit，而无需一次性重构整个项目。

```ts twoslash title="Kit"
import { Keypair, PublicKey } from "@solana/web3.js";
import { createSignerFromKeyPair } from "@solana/kit";
import {
  fromLegacyKeypair,
  fromLegacyPublicKey,
  fromLegacyTransactionInstruction,
  fromVersionedTransaction,
} from "@solana/compat";
// ---cut-start---
const transactionInstruction = null as unknown as Parameters<typeof fromLegacyTransactionInstruction>[0];
const versionedTransaction = null as unknown as Parameters<typeof fromVersionedTransaction>[0];
// ---cut-end---

// 转换 `PublicKeys`。
const address = fromLegacyPublicKey(new PublicKey("1234..5678"));

// 转换 `Keypairs`。
const cryptoKeypair = await fromLegacyKeypair(Keypair.generate());
const signer = await createSignerFromKeyPair(cryptoKeypair);

// 转换 `TransactionInstruction`。
const instruction = fromLegacyTransactionInstruction(transactionInstruction);

// 转换 `VersionedTransaction`。
const transaction = fromVersionedTransaction(versionedTransaction);
```
