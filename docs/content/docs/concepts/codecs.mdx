## 简介

工具包包含一个强大的序列化系统，称为编解码器。无论您是处理帐户数据、指令参数还是自定义二进制布局，编解码器都为您提供将结构化数据转换为字节以及反向转换的工具。

编解码器是可组合的、类型安全的且与环境无关的。它们旨在为跨 Solana 堆栈处理二进制数据提供灵活且一致的基础。

## 安装

编解码器**包含在 `@solana/kit` 库中**，但您也可以使用其独立包安装它们。

```package-install
@solana/codecs
```

请注意，`@solana/codecs` 包本身由几个较小的包组成，每个包都提供一组不同的编解码器助手。以下是包含编解码器的所有包的列表，如果您需要单独安装它们：

| 包                                                                                       | 描述                                                                       |
| ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| [`@solana/kit`](https://www.npmjs.com/package/@solana/kit)                               | 包含 `@solana/codecs`。                                                          |
| [`@solana/codecs`](https://www.npmjs.com/package/@solana/codecs)                         | 包含以下所有编解码器包。                                                              |
| [`@solana/codecs-core`](https://www.npmjs.com/package/@solana/codecs-core)              | 用于构建编解码器的核心类型和实用程序。                                                        |
| [`@solana/codecs-numbers`](https://www.npmjs.com/package/@solana/codecs-numbers)          | 用于各种大小和特征的数字的编解码器。                                                          |
| [`@solana/codecs-strings`](https://www.npmjs.com/package/@solana/codecs-strings)          | 用于各种编码和大小策略的字符串的编解码器。                                                          |
| [`@solana/codecs-data-structures`](https://www.npmjs.com/package/@solana/codecs-data-structures) | 用于各种数据结构的编解码器，例如对象、枚举、数组、映射等。                                                   |

## 什么是编解码器？

编解码器是一个对象，它知道如何将任何类型编码为 `Uint8Array`，以及如何将 `Uint8Array` 解码回该值。

无论我们使用哪种序列化策略，编解码器都会抽象其实现并提供一个简单的编码和解码接口。它们也是高度可组合的，允许我们从简单的构建块构建复杂的数据结构。

这是一个快速示例，用于编码和解码一个简单的 `Person` 类型。

```ts twoslash
import { Codec, addCodecSizePrefix, getUtf8Codec, getU32Codec, getStructCodec, ReadonlyUint8Array } from "@solana/kit";
// ---cut-before---
// 使用可组合的编解码器来构建复杂的数据结构。
type Person = { name: string; age: number };
const getPersonCodec = (): Codec<Person> =>
  getStructCodec([
    ["name", addCodecSizePrefix(getUtf8Codec(), getU32Codec())],
    ["age", getU32Codec()],
  ]);

// 使用您自己的编解码器来编码和解码数据。
const personCodec = getPersonCodec();
const encodedPerson = personCodec.encode({ name: "John", age: 42 });
const decodedPerson = personCodec.decode(encodedPerson);
```

## 组合编解码器

创建您自己的编解码器的最简单方法是组合您可用的[各种编解码器](#available-codecs)。

例如，考虑以下可用的编解码器：

- `getStructCodec`：为具有命名字段的对象创建编解码器。
- `getU32Codec`：为无符号 32 位整数创建编解码器。
- `getUtf8Codec`：为 UTF-8 字符串创建编解码器。
- `addCodecSizePrefix`：创建一个编解码器，该编解码器使用其长度作为编码数据的前缀。
- `getBooleanCodec`：使用单个字节为布尔值创建编解码器。

通过将它们组合在一起，我们可以为以下 `Person` 类型创建一个自定义编解码器。

```ts twoslash
import { Codec, addCodecSizePrefix, getUtf8Codec, getU32Codec, getStructCodec, getBooleanCodec } from "@solana/kit";
// ---cut-before---
type Person = {
  name: string;
  age: number;
  verified: boolean;
};

const getPersonCodec = (): Codec<Person> =>
  getStructCodec([
    ["name", addCodecSizePrefix(getUtf8Codec(), getU32Codec())],
    ["age", getU32Codec()],
    ["verified", getBooleanCodec()],
  ]);
```

此函数返回一个 `Codec` 对象，其中包含一个 `encode` 和 `decode` 函数，可用于将 `Person` 类型转换为和从 `Uint8Array` 类型转换。

```ts twoslash
import { Codec, addCodecSizePrefix, getUtf8Codec, getU32Codec, getStructCodec, getBooleanCodec } from "@solana/kit";
type Person = { name: string; age: number; verified: boolean };
const getPersonCodec = (): Codec<Person> =>
  getStructCodec([
    ["name", addCodecSizePrefix(getUtf8Codec(), getU32Codec())],
    ["age", getU32Codec()],
    ["verified", getBooleanCodec()],
  ]);
// ---cut-before---
const personCodec = getPersonCodec();
const bytes = personCodec.encode({ name: "John", age: 42, verified: true });
const person = personCodec.decode(bytes);
```

您可以使用大量的可组合编解码器库，使您能够组合复杂的类型。查看[可用编解码器](#available-codecs)部分以获取更多信息。如果您需要无法从现有编解码器组合的自定义编解码器，您可以随时创建自己的编解码器，正如我们将在下面的[“创建自定义编解码器”](#creating-custom-codecs)部分中看到的那样。

## 分离编码器和解码器

虽然编解码器可以同时编码和解码，但可以仅专注于编码或解码数据，从而使未使用的逻辑可以进行树摇。例如，这是我们之前仅使用编码器来编码 `Person` 类型的示例。

```ts twoslash
import {
  Encoder,
  addEncoderSizePrefix,
  getUtf8Encoder,
  getU32Encoder,
  getStructEncoder,
  getBooleanEncoder,
} from "@solana/kit";
type Person = { name: string; age: number; verified: boolean };
// ---cut-before---
const getPersonEncoder = (): Encoder<Person> =>
  getStructEncoder([
    ["name", addEncoderSizePrefix(getUtf8Encoder(), getU32Encoder())],
    ["age", getU32Encoder()],
    ["verified", getBooleanEncoder()],
  ]);

const bytes = getPersonEncoder().encode({ name: "John", age: 42, verified: true });
```

对于解码 `Person` 类型，也可以通过使用解码器来实现，如下所示。

```ts twoslash
import {
  Decoder,
  addDecoderSizePrefix,
  getUtf8Decoder,
  getU32Decoder,
  getStructDecoder,
  getBooleanDecoder,
} from "@solana/kit";
type Person = { name: string; age: number; verified: boolean };
const bytes = null as unknown as Uint8Array;
// ---cut-before---
const getPersonDecoder = (): Decoder<Person> =>
  getStructDecoder([
    ["name", addDecoderSizePrefix(getUtf8Decoder(), getU32Decoder())],
    ["age", getU32Decoder()],
    ["verified", getBooleanDecoder()],
  ]);

const person = getPersonDecoder().decode(bytes);
```

## 组合编码器和解码器

将编解码器分离为编码器和解码器对于库维护者来说尤其是一种好的做法，因为它允许他们的用户树摇他们不需要的任何编码器和/或解码器。但是，我们可能仍然希望为需要两者的用户提供一个方便的编解码器助手。

这就是为什么此库提供了一个 `combineCodec` 助手，用于从匹配的 `Encoder` 和 `Decoder` 创建一个 `Codec` 实例。

```ts twoslash
import { Codec, Encoder, Decoder, combineCodec } from "@solana/kit";
type Person = { name: string; age: number; verified: boolean };
const getPersonEncoder = null as unknown as () => Encoder<Person>;
const getPersonDecoder = null as unknown as () => Decoder<Person>;
// ---cut-before---
const getPersonCodec = (): Codec<Person> => combineCodec(getPersonEncoder(), getPersonDecoder());
```

这意味着库维护者可以为他们的所有类型提供编码器、解码器和编解码器，同时保持高效且可树摇。总之，我们建议在为库类型创建编解码器时采用以下模式。

```ts
type MyType = /* ... */;
const getMyTypeEncoder = (): Encoder<MyType> => { /* ... */ };
const getMyTypeDecoder = (): Decoder<MyType> => { /* ... */ };
const getMyTypeCodec = (): Codec<MyType> => combineCodec(
  getMyTypeEncoder(),
  getMyTypeDecoder()
);
```

## 不同的 `From` 和 `To` 类型

在创建编解码器时，允许编码类型比解码类型更宽松。一个很好的例子是 u64 数字编解码器：

```ts twoslash
import { Codec, getU64Codec } from "@solana/kit";
// ---cut-before---
const u64Codec: Codec<number | bigint, bigint> = getU64Codec();
```

正如您所看到的，第一个类型参数更宽松，因为它接受数字或大整数，而第二个类型参数仅接受大整数。这是因为在 _编码_ u64 数字时，您可以为了方便而提供 `bigint` 或 `number`。但是，当您解码 u64 数字时，您将始终获得一个 `bigint`，因为并非所有 u64 值都可以容纳在 JavaScript `number` 类型中。

```ts twoslash
import { getU64Codec } from "@solana/kit";
const u64Codec = getU64Codec();
// ---cut-before---
const bytes = u64Codec.encode(42);
const value = u64Codec.decode(bytes); // BigInt(42)
```

我们编码的类型“From”和解码的类型“To”之间的这种关系可以在 TypeScript 中概括为 `To extends From`。

这是另一个使用具有默认值的对象的示例。您可以在下面阅读有关 [transformCodec](#transform-codec) 助手的更多信息。

```ts twoslash
import {
  Codec,
  Encoder,
  Decoder,
  transformEncoder,
  getStructEncoder,
  getStructDecoder,
  addEncoderSizePrefix,
  addDecoderSizePrefix,
  getUtf8Encoder,
  getUtf8Decoder,
  getU32Encoder,
  getU32Decoder,
  combineCodec,
} from "@solana/kit";
// ---cut-before---
type Person = { name: string; age: number };
type PersonInput = { name: string; age?: number };

const getPersonEncoder = (): Encoder<PersonInput> =>
  transformEncoder(
    getStructEncoder([
      ["name", addEncoderSizePrefix(getUtf8Encoder(), getU32Encoder())],
      ["age", getU32Encoder()],
    ]),
    (input) => ({ ...input, age: input.age ?? 42 }),
  );

const getPersonDecoder = (): Decoder<Person> =>
  getStructDecoder([
    ["name", addDecoderSizePrefix(getUtf8Decoder(), getU32Decoder())],
    ["age", getU32Decoder()],
  ]);

const getPersonCodec = (): Codec<PersonInput, Person> => combineCodec(getPersonEncoder(), getPersonDecoder());
```

## 固定大小和可变大小的编解码器

还值得注意的是，编解码器可以是固定大小或可变大小的。

`FixedSizeCodecs` 具有一个 `fixedSize` 数字属性，该属性告诉我们其编码数据的大小（以字节为单位）。

```ts twoslash
import { FixedSizeCodec, getU32Codec } from "@solana/kit";
// ---cut-before---
const myCodec = getU32Codec();
myCodec satisfies FixedSizeCodec<number>;
myCodec.fixedSize; // 4 bytes.
```

另一方面，`VariableSizeCodecs` 不知道其编码数据的大小。相反，它们将从提供的编码数据或要编码的值中获取该信息。对于前者，我们可以简单地访问 `Uint8Array` 的长度。对于后者，它提供了一个 `getSizeFromValue`，该函数告诉我们提供的值的编码字节大小。

```ts twoslash
import { VariableSizeCodec, getUtf8Codec, getU32Codec, addCodecSizePrefix } from "@solana/kit";
// ---cut-before---
const myCodec = addCodecSizePrefix(getUtf8Codec(), getU32Codec());
myCodec satisfies VariableSizeCodec<string>;
myCodec.getSizeFromValue("hello world"); // 4 + 11 bytes.
```

另请注意，如果 `VariableSizeCodec` 受最大大小限制，则可以将其作为 `maxSize` 数字属性提供。

以下类型保护可用于标识和/或断言编解码器的大小：`isFixedSize`、`isVariableSize`、`assertIsFixedSize` 和 `assertIsVariableSize`。

最后，请注意，对于 `Encoders` 和 `Decoders` 也是如此。

- `FixedSizeEncoder` 具有一个 `fixedSize` 数字属性。
- `VariableSizeEncoder` 具有一个 `getSizeFromValue` 函数和一个可选的 `maxSize` 数字属性。
- `FixedSizeDecoder` 具有一个 `fixedSize` 数字属性。
- `VariableSizeDecoder` 具有一个可选的 `maxSize` 数字属性。

## 创建自定义编解码器

如果组合编解码器对您来说还不够，您可以使用 `createCodec` 函数来实现您自己的编解码器逻辑。此函数需要一个带有 `read` 和 `write` 函数的对象，该对象告诉我们如何从现有字节数组读取和写入。

`read` 函数接受要从中解码的 `bytes` 和我们应该开始读取的每个 `offset`。它返回一个包含两个项目的数组：

- 第一个项目应该是解码后的值。
- 第二个项目应该是下一个要读取的偏移量。

```ts twoslash
import { createCodec, Offset } from "@solana/kit";
const write = null as unknown as Parameters<typeof createCodec<number>>[0]["write"];
const fixedSize = null as unknown as 1;
// ---cut-before---
createCodec({
  read(bytes, offset) {
    const value = bytes[offset];
    return [value, offset + 1];
  },
  write,
  fixedSize,
});
```

相应地，`write` 函数接受要编码的 `value`，要将编码值写入的 `bytes` 数组以及应该写入的 `offset`。它应该对给定的值进行编码，将其插入到字节数组中，并提供下一个要写入的偏移量作为返回值。

```ts twoslash
import { createCodec } from "@solana/kit";
const read = null as unknown as Parameters<typeof createCodec<number>>[0]["read"];
const fixedSize = null as unknown as 1;
// ---cut-before---
createCodec({
  write(value: number, bytes, offset) {
    bytes.set([value], offset);
    return offset + 1;
  },
  read,
  fixedSize,
});
```

此外，我们必须指定编解码器的大小。如果我们定义的是 `FixedSizeCodec`，我们必须简单地提供 `fixedSize` 数字属性。对于 `VariableSizeCodecs`，我们必须提供 `getSizeFromValue` 函数，如上一节所述。

```ts twoslash
import { createCodec } from "@solana/kit";
type Config = Parameters<typeof createCodec<string>>[0];
const read = null as unknown as Config["read"];
const write = null as unknown as Config["write"];
// ---cut-before---
// FixedSizeCodec.
createCodec({
  fixedSize: 1,
  read,
  write,
});

// VariableSizeCodec.
createCodec({
  getSizeFromValue: (value: string) => value.length,
  read,
  write,
});
```

这是一个自定义编解码器的具体示例，该编解码器将任何无符号整数编码为单个字节。由于单个字节只能存储从 0 到 255 的整数，因此如果提供任何其他整数，它将取其模 256 以确保它可以容纳在单个字节中。因为它始终需要单个字节，所以该编解码器是大小为“1”的 `FixedSizeCodec`。

```ts twoslash
import { createCodec } from "@solana/kit";

const getModuloU8Codec = () =>
  createCodec<number>({
    fixedSize: 1,
    read(bytes, offset) {
      const value = bytes[offset];
      return [value, offset + 1];
    },
    write(value, bytes, offset) {
      bytes.set([value % 256], offset);
      return offset + 1;
    },
  });
```

请注意，也可以分别使用 `createEncoder` 和 `createDecoder` 函数来单独创建自定义编码器和解码器，然后像我们使用组合编解码器一样对它们使用 `combineCodec` 函数。

建议库维护者采用这种方法，因为它允许他们的用户树摇他们不需要的任何编码器和/或解码器。

这是我们之前的 modulo u8 示例，但已拆分为单独的 `Encoder`、`Decoder` 和 `Codec` 实例。

```ts twoslash
import { createEncoder, createDecoder, combineCodec } from "@solana/kit";

const getModuloU8Encoder = () =>
  createEncoder<number>({
    fixedSize: 1,
    write(value, bytes, offset) {
      bytes.set([value % 256], offset);
      return offset + 1;
    },
  });

const getModuloU8Decoder = () =>
  createDecoder<number>({
    fixedSize: 1,
    read(bytes, offset) {
      const value = bytes[offset];
      return [value, offset + 1];
    },
  });

const getModuloU8Codec = () => combineCodec(getModuloU8Encoder(), getModuloU8Decoder());
```

这是另一个返回 `VariableSizeCodec` 的示例。此示例将由 `a` 到 `z` 的字符组成的简单字符串转换为从 `1` 到 `26` 的数字缓冲区，其中 `0` 字节是空格。

```ts twoslash
import { createEncoder, createDecoder, combineCodec } from "@solana/kit";

const alphabet = " abcdefghijklmnopqrstuvwxyz";

const getCipherEncoder = () =>
  createEncoder<string>({
    getSizeFromValue: (value) => value.length,
    write(value, bytes, offset) {
      const bytesToAdd = [...value].map((char) => alphabet.indexOf(char));
      bytes.set(bytesToAdd, offset);
      return offset + bytesToAdd.length;
    },
  });

const getCipherDecoder = () =>
  createDecoder<string>({
    read(bytes, offset) {
      const value = [...bytes.slice(offset)].map((byte) => alphabet.charAt(byte)).join("");
      return [value, bytes.length];
    },
  });

const getCipherCodec = () => combineCodec(getCipherEncoder(), getCipherDecoder());
```

### addCodecSentinel [!toc] [#add-codec-sentinel]

限制编解码器大小的一种方法是使用警戒值。`addCodecSentinel` 函数允许我们在编码数据的末尾添加一个警戒值，并在解码时读取直到找到该警戒值。它接受任何编解码器和负责限制编码数据的 `Uint8Array` 警戒值。

```ts twoslash
import { addCodecSentinel, getUtf8Codec } from "@solana/kit";
// ---cut-before---
const codec = addCodecSentinel(getUtf8Codec(), new Uint8Array([255, 255]));
codec.encode("hello");
// 0x68656c6c6fffff
//   |        └-- 我们的警戒值。
//   └-- 我们的编码字符串。
```

请注意，警戒值_不得_存在于编码数据中，并且_必须_存在于解码数据中才能使其工作。如果不是这种情况，将抛出专用错误。

```ts twoslash
import { addCodecSentinel, getUtf8Codec } from "@solana/kit";
// ---cut-before---
const sentinel = new Uint8Array([108, 108]); // 'll'
const codec = addCodecSentinel(getUtf8Codec(), sentinel);

codec.encode("hello"); // 抛出：警戒值存在于编码数据中。
codec.decode(new Uint8Array([1, 2, 3])); // 抛出：解码数据中缺少警戒值。
```

还提供单独的 `addEncoderSentinel` 和 `addDecoderSentinel` 函数。

```ts twoslash
import { addEncoderSentinel, addDecoderSentinel, getUtf8Encoder, getUtf8Decoder } from "@solana/kit";
const sentinel = null as unknown as Uint8Array;
// ---cut-before---
const bytes = addEncoderSentinel(getUtf8Encoder(), sentinel).encode("hello");
const value = addDecoderSentinel(getUtf8Decoder(), sentinel).decode(bytes);
```

### addCodecSizePrefix [!toc] [#add-codec-size-prefix]

`addCodecSizePrefix` 函数允许我们将任何编解码器的字节大小存储为数字前缀，从而使我们能够将可变大小的编解码器限制为其实际大小。

编码时，编码数据的大小存储在编码数据本身之前。解码时，首先读取大小以了解接下来要读取多少字节。

例如，假设我们想使用 `u32` 大小前缀来表示可变大小的 base-58 字符串。下面是如何使用 `addCodecSizePrefix` 函数来实现这一点。

```ts twoslash
import { addCodecSizePrefix, getBase58Codec, getU32Codec } from "@solana/kit";
// ---cut-before---
const getU32Base58Codec = () => addCodecSizePrefix(getBase58Codec(), getU32Codec());

getU32Base58Codec().encode("hello world");
// 0x0b00000068656c6c6f20776f726c64
//   |       └-- 我们的编码 base-58 字符串。
//   └-- 我们的编码 u32 大小前缀。
```

您还可以使用 `addEncoderSizePrefix` 和 `addDecoderSizePrefix` 函数来分离您的编解码器逻辑，如下所示：

```ts twoslash
import {
  addEncoderSizePrefix,
  addDecoderSizePrefix,
  getBase58Encoder,
  getBase58Decoder,
  getU32Encoder,
  getU32Decoder,
  combineCodec,
} from "@solana/kit";
// ---cut-before---

const getU32Base58Decoder = () => addDecoderSizePrefix(getBase58Decoder(), getU32Decoder());

### offsetCodec [!toc] [#offset-codec]

`offsetCodec` 函数是一个强大的编解码器原语，允许我们将给定编解码器的偏移量向前或向后移动。它接受一个或两个函数，这些函数接受当前偏移量并返回一个新的偏移量。

为了理解这是如何工作的，让我们看下面的 `biggerU32Codec` 示例，该示例通过使用 [resizeCodec](#resize-codec) 助手将 `u32` 数字编码到 8 字节缓冲区中。

```ts twoslash
import { resizeCodec, getU32Codec } from "@solana/kit";
// ---cut-before---
const biggerU32Codec = resizeCodec(getU32Codec(), (size) => size + 4);
biggerU32Codec.encode(0xffffffff);
// 0xffffffff00000000
//   |       └-- 由 resizeCodec 函数引起的空缓冲区空间。
//   └-- 我们的编码 u32 数字。
```

现在，假设我们想将该编解码器的偏移量向前移动 2 个字节，以便编码数字位于缓冲区的中间。为了实现这一点，我们可以使用 `offsetCodec` 助手并提供一个 `preOffset` 函数，该函数向前移动编解码器的“pre-offset”2 个字节。

```ts twoslash
import { offsetCodec, resizeCodec, getU32Codec } from "@solana/kit";
const biggerU32Codec = resizeCodec(getU32Codec(), (size) => size + 4);
// ---cut-before---
const u32InTheMiddleCodec = offsetCodec(biggerU32Codec, {
  preOffset: ({ preOffset }) => preOffset + 2,
});
u32InTheMiddleCodec.encode(0xffffffff);
// 0x0000ffffffff0000
//       └-- 我们的编码 u32 数字现在位于缓冲区的中间。
```

我们将此偏移量称为“pre-offset”，因为一旦内部编解码器被编码或解码，将返回一个附加的偏移量，我们将其称为“post-offset”。这个“post-offset”很重要，因为除非我们到达编解码器的末尾，否则它将被任何进一步的编解码器用于继续编码或解码数据。

默认情况下，该“post-offset”只是“pre-offset”和编码或解码的内部数据大小之和。

```ts twoslash
import { offsetCodec, resizeCodec, getU32Codec } from "@solana/kit";
const biggerU32Codec = resizeCodec(getU32Codec(), (size) => size + 4);
// ---cut-before---
const u32InTheMiddleCodec = offsetCodec(biggerU32Codec, {
  preOffset: ({ preOffset }) => preOffset + 2,
});
u32InTheMiddleCodec.encode(0xffffffff);
// 0x0000ffffffff0000
//   |   |       └-- Post-offset。
//   |   └-- 新的 pre-offset：原始 pre-offset + 2。
//   └-- Pre-offset：我们在调整它之前的原始 pre-offset。
```

但是，您也可以提供一个 `postOffset` 函数来调整“post-offset”。例如，让我们也将“post-offset”向前推送 2 个字节，以便任何进一步的编解码器都将在我们的 8 字节 `u32` 数字的末尾开始执行其工作。

```ts twoslash
import { offsetCodec, resizeCodec, getU32Codec } from "@solana/kit";
const biggerU32Codec = resizeCodec(getU32Codec(), (size) => size + 4);
// ---cut-before---
const u32InTheMiddleCodec = offsetCodec(biggerU32Codec, {
  preOffset: ({ preOffset }) => preOffset + 2,
  postOffset: ({ postOffset }) => postOffset + 2,
});
u32InTheMiddleCodec.encode(0xffffffff);
// 0x0000ffffffff0000
//   |   |       |   └-- 新的 post-offset：原始 post-offset + 2。
//   |   |       └-- Post-offset：我们在调整它之前的原始 post-offset。
//   |   └-- 新的 pre-offset：原始 pre-offset + 2。
//   └-- Pre-offset：我们在调整它之前的原始 pre-offset。
```

`preOffset` 和 `postOffset` 函数都提供以下属性：

- `bytes`：正在编码或解码的整个字节数组。
- `preOffset`：原始的和未经更改的 pre-offset。
- `wrapBytes`：一个助手函数，用于将给定的偏移量围绕字节数组长度包装。例如，`wrapBytes(-1)` 将引用字节数组的最后一个字节。

此外，后偏移函数```ts twoslash
import {
  offsetEncoder,
  resizeEncoder,
  getU32Encoder,
  offsetDecoder,
  resizeDecoder,
  getU32Decoder,
  combineCodec,
} from "@solana/kit";
const biggerU32Encoder = resizeEncoder(getU32Encoder(), (size) => size + 4);
const biggerU32Decoder = resizeDecoder(getU32Decoder(), (size) => size + 4);
// ---cut-before---
const getU32InTheMiddleEncoder = () => offsetEncoder(biggerU32Encoder, { preOffset: ({ preOffset }) => preOffset + 2 });
const getU32InTheMiddleDecoder = () => offsetDecoder(biggerU32Decoder, { preOffset: ({ preOffset }) => preOffset + 2 });
const getU32InTheMiddleCodec = () => combineCodec(getU32InTheMiddleEncoder(), getU32InTheMiddleDecoder());
```

### resizeCodec [!toc] [#resize-codec]

`resizeCodec` 辅助函数通过接受一个函数来重新定义给定 codec 的大小，该函数接收 codec 的当前大小并返回一个新大小。这适用于固定大小和可变大小的 codec。

```ts twoslash
import { resizeCodec, getU32Codec, getUtf8Codec } from "@solana/kit";
// ---cut-before---
// Fixed-size codec.
// 固定大小的 codec。
const getBiggerU32Codec = () => resizeCodec(getU32Codec(), (size) => size + 4);
getBiggerU32Codec().encode(42);
// 0x2a00000000000000
//   |       └-- 空白缓冲区空间由 resizeCodec 函数引起。
//   └-- 我们编码的 u32 数字。

// Variable-size codec.
// 可变大小的 codec。
const getBiggerUtf8Codec = () => resizeCodec(getUtf8Codec(), (size) => size + 4);
getBiggerUtf8Codec().encode("ABC");
// 0x41424300000000
//   |     └-- 空白缓冲区空间由 resizeCodec 函数引起。
//   └-- 我们编码的字符串。
```

请注意，`resizeCodec` 函数不会更改任何编码或解码的字节，它只是告诉 `encode` 和 `decode` 函数 `Uint8Array` 在委托给它们各自的 `write` 和 `read` 函数之前应该有多大。实际上，当直接使用 `write` 和 `read` 函数时，这会被完全绕过。例如：

```ts twoslash
import { resizeCodec, getU32Codec } from "@solana/kit";
// ---cut-before---
const getBiggerU32Codec = () => resizeCodec(getU32Codec(), (size) => size + 4);

// Using the encode function.
// 使用 encode 函数。
getBiggerU32Codec().encode(42);
// 0x2a00000000000000

// Using the lower-level write function.
// 使用底层 write 函数。
const myCustomBytes = new Uint8Array(4);
getBiggerU32Codec().write(42, myCustomBytes, 0);
// 0x2a000000
```

那么什么时候使用 `resizeCodec` 函数才有意义呢？此函数在与 [offsetCodec](#offset-codec) 函数结合使用时特别有用。虽然 `offsetCodec` 可以帮助我们将偏移量向前推进 - 例如，跳过一些填充 - 但它不会改变编码数据的大小，这意味着最后的字节将被我们向前推进的偏移量截断。`resizeCodec` 函数可以用来解决这个问题。例如，以下是我们如何一起使用 `resizeCodec` 和 `offsetCodec` 函数来创建一个包含一些填充的结构体 codec。

```ts twoslash
import { getStructCodec, getUtf8Codec, getU32Codec, offsetCodec, resizeCodec, fixCodecSize } from "@solana/kit";
// ---cut-before---
const personCodec = getStructCodec([
  ["name", fixCodecSize(getUtf8Codec(), 8)],
  // There is a 4-byte padding between name and age.
  // 姓名和年龄之间有 4 字节的填充。
  [
    "age",
    offsetCodec(
      resizeCodec(getU32Codec(), (size) => size + 4),
      { preOffset: ({ preOffset }) => preOffset + 4 },
    ),
  ],
]);

personCodec.encode({ name: "Alice", age: 42 });
// 0x416c696365000000000000002a000000
//   |               |       └-- 我们编码的 u32 (42)。
//   |               └-- 我们跳过的 4 字节填充。
//   └-- 我们 8 字节编码的字符串 ("Alice")。
```

请注意，这可以使用以这种方式实现的 [padLeftCodec](#pad-left-codec) 辅助函数来实现。

`resizeEncoder` 和 `resizeDecoder` 函数也可用于将您的 codec 逻辑拆分为可 tree-shake 的函数。

```ts twoslash
import { resizeEncoder, resizeDecoder, getU32Encoder, getU32Decoder, combineCodec } from "@solana/kit";
// ---cut-before---
const getBiggerU32Encoder = () => resizeEncoder(getU32Encoder(), (size) => size + 4);
const getBiggerU32Decoder = () => resizeDecoder(getU32Decoder(), (size) => size + 4);
const getBiggerU32Codec = () => combineCodec(getBiggerU32Encoder(), getBiggerU32Decoder());
```

### transformCodec [!toc] [#transform-codec]

通过提供两个映射函数，可以将 `Codec<T>` 转换为 `Codec<U>`：一个是从 `T` 到 `U`，另一个是相反的映射。

例如，以下介绍如何将 `u32` 整数映射到该数字的 `string` 表示形式。

```ts twoslash
import { transformCodec, getU32Codec } from "@solana/kit";
// ---cut-before---
const getStringU32Codec = () =>
  transformCodec(
    getU32Codec(),
    (integerAsString: string): number => parseInt(integerAsString),
    (integer: number): string => integer.toString(),
  );

getStringU32Codec().encode("42"); // new Uint8Array([42])
getStringU32Codec().decode(new Uint8Array([42])); // "42"
```

如果 `Codec` 具有[不同的 From 和 To 类型](#different-from-and-to-types)，例如 `Codec<OldFrom, OldTo>`，并且我们想要将其映射到 `Codec<NewFrom, NewTo>`，我们必须提供从 `NewFrom` 映射到 `OldFrom` 以及从 `OldTo` 映射到 `NewTo` 的函数。

为了说明这一点，让我们采用之前的 `getStringU32Codec` 示例，但使用 `getU64Codec` codec，因为它返回 `Codec<number | bigint, bigint>`。此外，让我们让我们的 `getStringU64Codec` 函数返回 `Codec<number | string, string>`，以便它在编码值时也接受数字。以下是我们的映射函数的样子：

```ts twoslash
import { transformCodec, getU64Codec } from "@solana/kit";
// ---cut-before---
const getStringU64Codec = () =>
  transformCodec(
    getU64Codec(),
    (integerInput: number | string): number | bigint =>
      typeof integerInput === "string" ? BigInt(integerInput) : integerInput,
    (integer: bigint): string => integer.toString(),
  );
```

请注意，映射解码类型的第二个函数是可选的。这意味着，您可以省略它以简单地更新或放宽要编码的类型，同时保持解码类型不变。

这对于为对象结构提供默认值特别有用。例如，以下是我们如何映射 `Person` codec 以为其 `age` 属性赋予默认值。

```ts twoslash
import { transformCodec, getStructCodec, Codec } from "@solana/kit";
// ---cut-before---
type Person = { name: string; age: number };
type PersonInput = { name: string; age?: number };
// ---cut-start---
const getPersonCodec = null as unknown as () => Codec<Person>;
// ---cut-end---
const getPersonWithDefaultValueCodec = (): Codec<PersonInput, Person> =>
  transformCodec(getPersonCodec(), (person: PersonInput): Person => ({ ...person, age: person.age ?? 42 }));
```

存在类似的辅助程序来映射 `Encoder` 和 `Decoder` 实例，允许您将 codec 逻辑分隔为可 tree-shake 的函数。以下是以这种方式编写的 `getStringU32Codec`。

```ts twoslash
import { transformEncoder, transformDecoder, getU32Encoder, getU32Decoder, combineCodec } from "@solana/kit";
// ---cut-before---
const getStringU32Encoder = () =>
  transformEncoder(getU32Encoder(), (integerAsString: string): number => parseInt(integerAsString));
const getStringU32Decoder = () => transformDecoder(getU32Decoder(), (integer: number): string => integer.toString());
const getStringU32Codec = () => combineCodec(getStringU32Encoder(), getStringU32Decoder());
```

### getI8Codec [!toc] [#get-i8-codec]

编码和解码 **有符号 8 位整数**。它支持从 -127 (`-2^7`) 到 128 (`2^7 - 1`) 的值。

值可以以 `number` 或 `bigint` 的形式提供，但解码后的值始终是一个 `number`。

```ts twoslash
import { getI8Codec } from "@solana/kit";

### getI16Codec [!toc] [#get-i16-codec]

值可以以 `number` 或 `bigint` 的形式提供，但解码后的值始终是一个 `number`。可以使用 `endian` 选项指定字节序。默认值为 `Endian.Little`。

import { getI16Codec, Endian } from "@solana/kit";

const beCodec = getI16Codec({ endian: Endian.Big });

### getShortU16Codec [!toc] [#get-short-u16-codec]

根据编码后的值，使用 **1 到 3 个字节**编码和解码 **无符号整数**。它支持从 0 到 4,194,303 (`2^22 - 1`) 的值。

值越大，它使用的字节就越多。

- 如果该值 `<= 0x7f` (127)，它将存储在 **单个字节**中，并且第一位设置为 `0` 以指示该值的结束。
- 否则，第一位设置为 `1` 以指示该值在下一个字节中继续，下一个字节遵循相同的模式。
- 此过程一直重复，直到该值完全编码为最多 3 个字节。第三个也是最后一个字节（如果需要）使用所有 8 位来存储剩余值。

换句话说，编码方案遵循以下结构：

```txt
0XXXXXXX                   <- Values 0 to 127 (1 byte)
// 0 到 127 的值（1 个字节）
1XXXXXXX 0XXXXXXX          <- Values 128 to 16,383 (2 bytes)
// 128 到 16,383 的值（2 个字节）
1XXXXXXX 1XXXXXXX XXXXXXXX <- Values 16,384 to 4,194,303 (3 bytes)
// 16,384 到 4,194,303 的值（3 个字节）
```

值可以以 `number` 或 `bigint` 的形式提供，但解码后的值始终是一个 `number`。

```ts twoslash
import { getShortU16Codec } from "@solana/kit";
// ---cut-before---
const codec = getShortU16Codec();
const bytes1 = codec.encode(42); // 0x2a
const bytes2 = codec.encode(128); // 0x8001
const bytes3 = codec.encode(16384); // 0x808001

codec.decode(bytes1); // 42
codec.decode(bytes2); // 128
codec.decode(bytes3); // 16384
```

`getShortU16Encoder` 和 `getShortU16Decoder` 函数也可用。

### getBase10Codec [!toc] [#get-base10-codec]

编码和解码 **Base 10 字符串**。

```ts twoslash

// ---cut-before---

const bytes = codec.encode("1024"); // 0x0400
const value = codec.decode(bytes); // "1024"
```

此 codec 不强制执行大小边界。它将编码和解码表示字符串所需的所有字节。要向 codec 添加大小约束，可以使用实用程序函数，例如 [`fixCodecSize`](#fix-codec-size)、[`addCodecSizePrefix`](#add-codec-size-prefix) 或 [`addCodecSentinel`](#add-codec-sentinel)。

```ts twoslash
import { getBase10Codec, fixCodecSize, addCodecSizePrefix, getU32Codec, addCodecSentinel } from "@solana/kit";
// ---cut-before---
fixCodecSize(getBase10Codec(), 4).encode("1024");
// 0x04000000 (padded to 4 bytes)
// (填充到 4 个字节)

addCodecSizePrefix(getBase10Codec(), getU32Codec()).encode("1024");
// 0x020000000400
//   |       └-- 内容的 2 个字节。
//   └-- 4 字节前缀，告诉我们读取 2 个字节。

addCodecSentinel(getBase10Codec(), new Uint8Array([0xff, 0xff])).encode("1024");
// 0x0400ffff
//   |   └-- 指示内容结尾的哨兵。
//   └-- 内容的 2 个字节。
```

### getBaseXResliceCodec [!toc] [#get-baseX-reslice-codec]

## 数据结构列表 [!toc]

### getArrayCodec [!toc] [#get-array-codec]

`getArrayCodec` 函数接受任何 `T` 类型的 codec，并返回 `Array<T>` 类型的 codec。

```ts twoslash
import { getArrayCodec, getU8Codec } from "@solana/kit";
// ---cut-before---
const codec = getArrayCodec(getU8Codec());
const bytes = codec.encode([1, 2, 3]); // 0x03000000010203
const array = codec.decode(bytes); // [1, 2, 3]
```

默认情况下，在编码项目之前，数组的大小以 `u32` 前缀的形式存储。

```ts twoslash
import { getArrayCodec, getU8Codec } from "@solana/kit";
// ---cut-before---
getArrayCodec(getU8Codec()).encode([1, 2, 3]);
// 0x03000000010203
//   |       └-- 每个 1 字节的 3 个项目。
//   └-- 4 字节前缀告诉我们要读取 3 个项目。
```

但是，你可以使用 `size` 选项来配置此行为。它可以是以下三种策略之一：

- `Codec<number>`：当提供数字 codec 时，该 codec 将用于编码和解码大小前缀。
- `number`：当提供数字时，该 codec 将期望数组中具有固定数量的项目。当尝试编码长度不同的数组时，将引发错误。
- `"remainder"`：当字符串 `"remainder"` 作为大小传递时，该 codec 将使用剩余的字节来编码/解码其项目。这意味着大小不会被存储或提前知道，而是简单地从缓冲区的其余部分推断出来。例如，如果我们有一个 `u16` 数字数组并剩下 10 个字节，我们就知道该数组中有 5 个项目。

```ts twoslash
import { getArrayCodec, getU8Codec, getU16Codec } from "@solana/kit";
// ---cut-before---
getArrayCodec(getU8Codec(), { size: getU16Codec() }).encode([1, 2, 3]);
// 0x0300010203
//   |   └-- 每个 1 字节的 3 个项目。
//   └-- 2 字节前缀告诉我们要读取 3 个项目。

getArrayCodec(getU8Codec(), { size: 3 }).encode([1, 2, 3]);
// 0x010203
//   └-- 每个 1 字节的 3 个项目。数组中必须始终有 3 个项目。

getArrayCodec(getU8Codec(), { size: "remainder" }).encode([1, 2, 3]);
// 0x010203
//   └-- 每个 1 字节的 3 个项目。大小是从剩余的字节推断出来的。
```

`getArrayEncoder` 和 `getArrayDecoder` 函数也可用。

### getBytesCodec [!toc] [#get-bytes-codec]

`getBytesCodec` 函数返回一个 `Codec<Uint8Array>`，这意味着它在 `Uint8Arrays` 之间进行转换！虽然这可能看起来有点没用，但当它被组合到其他 codec 中时可能会很有用。例如，你可以在 struct codec 中使用它来说明某个特定字段应该保持不序列化。

```ts twoslash
import { getBytesCodec } from "@solana/kit";
// ---cut-before---
const codec = getBytesCodec();
const bytes = codec.encode(new Uint8Array([42])); // 0x2a
const value = codec.decode(bytes); // 0x2a
```

`getBytesCodec` 函数将使用尽可能多的字节来编码和解码 `Uint8Arrays`。如果你想限制此 codec 使用的字节数，你可以将其与诸如 [`fixCodecSize`](#fix-codec-size)，[`addCodecSizePrefix`](#add-codec-size-prefix) 或 [`addCodecSentinel`](#add-codec-sentinel) 等实用程序结合使用。

```ts twoslash
import { getBytesCodec, fixCodecSize, addCodecSizePrefix, getU32Codec, addCodecSentinel } from "@solana/kit";
// ---cut-before---
const value = new Uint8Array([42, 43]); // 0x2a2b

fixCodecSize(getBytesCodec(), 4).encode(value);
// 0x2a2b0000 (padded to 4 bytes)

addCodecSizePrefix(getBytesCodec(), getU32Codec()).encode(value);
// 0x020000002a2b
//   |       └-- 内容的 2 个字节。
//   └-- 4 字节前缀告诉我们要读取 2 个字节。

addCodecSentinel(getBytesCodec(), new Uint8Array([0xff, 0xff])).encode(value);
// 0x2a2bffff
//   |   └-- 发出内容结束信号的 sentinel。
//   └-- 内容的 2 个字节。
```

`getBytesEncoder` 和 `getBytesDecoder` 函数也可用。

### getConstantCodec [!toc] [#get-constant-codec]

`getConstantCodec` 函数接受任何 `Uint8Array` 并返回一个 `Codec<void>`。编码时，它将按原样设置提供的 `Uint8Array`。解码时，它将断言下一个字节包含提供的 `Uint8Array` 并向前移动偏移量。

```ts twoslash
import { getConstantCodec } from "@solana/kit";
// ---cut-before---
const codec = getConstantCodec(new Uint8Array([1, 2, 3]));

codec.encode(undefined); // 0x010203
codec.decode(new Uint8Array([1, 2, 3])); // undefined
codec.decode(new Uint8Array([1, 2, 4])); // Throws an error.
```

`getConstantEncoder` and `getConstantDecoder` 函数也是可用的。

### getDiscriminatedUnionCodec [!toc] [#get-discriminated-union-codec]

在 Rust 中，枚举是强大的数据类型，其变体可以是以下之一：

- 一个空的变体 — 例如 `enum Message { Quit }`。
- 一个元组变体 — 例如 `enum Message { Write(String) }`。
- 一个结构体变体 — 例如 `enum Message { Move { x: i32, y: i32 } }`。

虽然我们在 JavaScript 中没有这么强大的枚举，但我们可以使用对象的联合在 TypeScript 中模拟它们，这样每个对象都由一个特定的字段区分。**我们称之为可区分联合**。

我们使用一个名为 `__kind` 的特殊字段来区分可区分联合的不同变体。此外，由于所有变体都是对象，我们可以使用 `fields` 属性来包装元组变体的数组。这是一个例子。

```ts twoslash
type Message =
  | { __kind: "quit" } // 空的变体.
  | { __kind: "write"; fields: [string] } // 元组变体.
  | { __kind: "move"; x: number; y: number }; // 结构体变体.
```

`getDiscriminatedUnionCodec` 函数帮助我们编码和解码这些可区分联合。

它需要鉴别器和每个变体的 codec 作为第一个参数。与 [getStructCodec](#get-struct-codec) 类似，这些定义为变体元组的数组，其中第一个项目是变体的鉴别器，第二个项目是它的 codec。由于空的变体没有要编码的数据，因此它们只使用不执行任何操作的 [getUnitCodec](#get-unit-codec)。

这是我们如何为先前的示例创建可区分联合 codec。

```ts twoslash
import {
  getDiscriminatedUnionCodec,
  getUnitCodec,
  getStructCodec,
  getTupleCodec,
  getUtf8Codec,
  getU32Codec,
  addCodecSizePrefix,
  getI32Codec,
} from "@solana/kit";
// ---cut-before---
const messageCodec = getDiscriminatedUnionCodec([
  // 空的变体.
  ["quit", getUnitCodec()],

  // 元组变体.
  ["write", getStructCodec([["fields", getTupleCodec([addCodecSizePrefix(getUtf8Codec(), getU32Codec())])]])],

  // 结构体变体.
  [
    "move",
    getStructCodec([
      ["x", getI32Codec()],
      ["y", getI32Codec()],
    ]),
  ],
]);
```

这是我们如何使用这样的 codec 来编码可区分联合。请注意，默认情况下，它们使用 `u8` 数字前缀来区分不同类型的变体。

```ts twoslash
import {
  getDiscriminatedUnionCodec,
  getUnitCodec,
  getStructCodec,
  getTupleCodec,
  getUtf8Codec,
  getU32Codec,
  addCodecSizePrefix,
  getI32Codec,
} from "@solana/kit";
const messageCodec = getDiscriminatedUnionCodec([
  // 空的变体.
  ["quit", getUnitCodec()],

  // 元组变体.
  ["write", getStructCodec([["fields", getTupleCodec([addCodecSizePrefix(getUtf8Codec(), getU32Codec())])]])],

  // 结构体变体.
  [
    "move",
    getStructCodec([
      ["x", getI32Codec()],
      ["y", getI32Codec()],
    ]),
  ],
]);
// ---cut-before---
messageCodec.encode({ __kind: "quit" });
// 0x00
//   └-- 1-字节鉴别器 (索引 0 — "quit" 变体).

messageCodec.encode({ __kind: "write", fields: ["Hi"] });
// 0x01020000004869
//   | |       └-- utf8 字符串内容 ("Hi").
//   | └-- u32 字符串前缀 (2 characters).
//   └-- 1-字节鉴别器 (索引 1 — "write" 变体).

messageCodec.encode({ __kind: "move", x: 5, y: 6 });
// 0x020500000006000000
//   | |       └-- 字段 y (6).
//   | └-- 字段 x (5).
//   └-- 1-字节鉴别器 (索引 2 — "move" 变体).
```

但是，你可以提供一个数字 codec 作为 `getDiscriminatedUnionCodec` 函数的 `size` 选项来自定义该行为。

```ts twoslash
import {
  getDiscriminatedUnionCodec,
  getUnitCodec,
  getStructCodec,
  getTupleCodec,
  getUtf8Codec,
  getU32Codec,
  addCodecSizePrefix,
  getI32Codec,
} from "@solana/kit";
const quitCodec = getUnitCodec();
const writeCodec = getStructCodec([["fields", getTupleCodec([addCodecSizePrefix(getUtf8Codec(), getU32Codec())])]]);
const moveCodec = getStructCodec([
  ["x", getI32Codec()],
  ["y", getI32Codec()],
]);
// ---cut-before---
const u32MessageCodec = getDiscriminatedUnionCodec(
  [
    ["quit", quitCodec],
    ["write", writeCodec],
    ["move", moveCodec],
  ],
  { size: getU32Codec() },
);

u32MessageCodec.encode({ __kind: "quit" });
// 0x00000000
//   └------┘ 4-字节鉴别器 (索引 0).

u32MessageCodec.encode({ __kind: "write", fields: ["Hi"] });
// 0x01000000020000004869
//   └------┘ 4-字节鉴别器 (索引 1).

u32MessageCodec.encode({ __kind: "move", x: 5, y: 6 });
// 0x020000000500000006000000
//   └------┘ 4-字节鉴别器 (索引 2).
```

你还可以自定义鉴别器属性（默认为 `__kind`），方法是将所需的属性名称作为 `discriminator` 选项提供，如下所示：

### getEnumCodec [!toc] [#get-enum-codec]

`getEnumCodec` 函数接受一个 JavaScript 枚举构造函数，并返回一个用于编码和解码该枚举值的 codec。

```ts twoslash
import { getEnumCodec } from "@solana/kit";
// ---cut-before---
enum Direction {
  Left,
  Right,
}

const codec = getEnumCodec(Direction);
const bytes = codec.encode(Direction.Left); // 0x00
const direction = codec.decode(bytes); // Direction.Left
```

在编码枚举时，你可以提供枚举变量的值 - 例如 `Direction.Left` - 或它的键 - 例如 `'Left'`。

```ts twoslash
import { getEnumCodec } from "@solana/kit";
enum Direction {
  Left,
  Right,
}
// ---cut-before---
getEnumCodec(Direction).encode(Direction.Left); // 0x00
getEnumCodec(Direction).encode(Direction.Right); // 0x01
getEnumCodec(Direction).encode("Left"); // 0x00
getEnumCodec(Direction).encode("Right"); // 0x01
```

默认情况下，使用 `u8` 数字来存储枚举值。 但是，可以将数字 codec 作为 `size` 选项传递以配置该行为。

```ts twoslash
import { getEnumCodec, getU32Codec } from "@solana/kit";
enum Direction {
  Left,
  Right,
}
// ---cut-before---
const u32DirectionCodec = getEnumCodec(Direction, { size: getU32Codec() });
u32DirectionCodec.encode(Direction.Left); // 0x00000000
u32DirectionCodec.encode(Direction.Right); // 0x01000000
```

此函数还适用于词法枚举 - 例如 `enum Direction { Left = '←' }` - 显式数值枚举 - 例如 `enum Speed { Left = 50 }` - 以及混合了这两种枚举的混合枚举。

```ts twoslash
import { getEnumCodec } from "@solana/kit";
// ---cut-before---
enum Numbers {
  One,
  Five = 5,
  Six,
  Nine = "nine",
}

getEnumCodec(Numbers).encode(Numbers.One); // 0x00
getEnumCodec(Numbers).encode(Numbers.Five); // 0x01
getEnumCodec(Numbers).encode(Numbers.Six); // 0x02
getEnumCodec(Numbers).encode(Numbers.Nine); // 0x03
getEnumCodec(Numbers).encode("One"); // 0x00
getEnumCodec(Numbers).encode("Five"); // 0x01
getEnumCodec(Numbers).encode("Six"); // 0x02
getEnumCodec(Numbers).encode("Nine"); // 0x03
```

请注意，默认情况下，枚举变量的索引用于编码枚举的值。 例如，在上面的示例中，`Numbers.Five` 被编码为 `0x01`，即使它的值是 `5`。对于词法枚举也是如此。

但是，当处理具有显式值的数值枚举时，你可以使用 `useValuesAsDiscriminators` 选项来编码枚举变量的值，而不是它的索引。

```ts twoslash
import { getEnumCodec } from "@solana/kit";
// ---cut-before---
enum Numbers {
  One,
  Five = 5,
  Six,
  Nine = 9,
}

const codec = getEnumCodec(Numbers, { useValuesAsDiscriminators: true });
codec.encode(Numbers.One); // 0x00
codec.encode(Numbers.Five); // 0x05
codec.encode(Numbers.Six); // 0x06
codec.encode(Numbers.Nine); // 0x09
codec.encode("One"); // 0x00
codec.encode("Five"); // 0x05
codec.encode("Six"); // 0x06
codec.encode("Nine"); // 0x09
```

请注意，当在包含词法值的枚举上使用 `useValuesAsDiscriminators` 选项时，将引发错误。

```ts twoslash
import { getEnumCodec } from "@solana/kit";
// ---cut-before---
enum Lexical {
  One,
  Two = "two",
}
getEnumCodec(Lexical, { useValuesAsDiscriminators: true }); // Throws an error.
```

`getEnumEncoder` and `getEnumDecoder` 函数也是可用的。

### getHiddenPrefixCodec [!toc] [#get-hidden-prefix-codec]

`getHiddenPrefixCodec` 函数允许我们将隐藏的 `Codec<void>` 列表预先添加到给定的 codec。

编码时，隐藏的 codec 将在主 codec 之前编码，并且偏移量将相应地移动。 解码时，将解码隐藏的 codec，但仅返回主 codec 的结果。 当创建包含不应包含在最终类型中的常量值的数据结构时，这特别有用。

```ts twoslash
import { getHiddenPrefixCodec, getConstantCodec, getU16Codec } from "@solana/kit";
// ---cut-before---
const codec = getHiddenPrefixCodec(getU16Codec(), [
  getConstantCodec(new Uint8Array([1, 2, 3])),
  getConstantCodec(new Uint8Array([4, 5, 6])),
]);

codec.encode(42);
// 0x0102030405062a00
//   |     |     └-- 我们的主 u16 codec (value = 42).
//   |     └-- 我们的第二个隐藏前缀 codec.
//   └-- 我们的第一个隐藏前缀 codec.

codec.decode(new Uint8Array([1, 2, 3, 4, 5, 6, 42, 0])); // 42
```

`getHiddenPrefixEncoder` 和 `getHiddenPrefixDecoder` 函数也可用。

### getLiteralUnionCodec [!toc] [#get-literal-union-codec]

`getLiteralUnionCodec` 函数接受文字值数组 - 例如 `string`、`number`、`boolean` 等 - 并返回一个通过使用它们在数组中的索引来编码和解码这些值的 codec。 它使用 TypeScript 联合来表示所有可能的值。

```ts twoslash
import { getLiteralUnionCodec, FixedSizeCodec } from "@solana/kit";
// ---cut-before---
const codec = getLiteralUnionCodec(["left", "right", "up", "down"]);
codec satisfies FixedSizeCodec<"left" | "right" | "up" | "down">;

const bytes = codec.encode("left"); // 0x00
const value = codec.decode(bytes); // 'left'
```

默认情况下，它使用一个 `u8` 数字来存储值的索引。 但是，你可以提供一个数字 codec 作为 `getLiteralUnionCodec` 函数的 `size` 选项来自定义该行为。

```ts twoslash
import { getLiteralUnionCodec, getU32Codec } from "@solana/kit";
// ---cut-before---
const codec = getLiteralUnionCodec(["left", "right", "up", "down"], {
  size: getU32Codec(),
});

codec.encode("left"); // 0x00000000
codec.encode("right"); // 0x01000000
codec.encode("up"); // 0x02000000
codec.encode("down"); // 0x03000000
```

`getLiteralUnionEncoder` 和 `getLiteralUnionDecoder` 函数也可用。

### getMapCodec [!toc] [#get-map-codec]

`getMapCodec` 函数接受 `K` 和 `V` 类型的两个 codec，并返回 `Map<K, V>` 类型的 codec。

```ts twoslash
import { getMapCodec, getU8Codec, getUtf8Codec, fixCodecSize } from "@solana/kit";
// ---cut-before---
const keyCodec = fixCodecSize(getUtf8Codec(), 8);
const valueCodec = getU8Codec();
const codec = getMapCodec(keyCodec, valueCodec);

const bytes = codec.encode(new Map([["alice", 42]])); // 0x01000000616c6963650000002a
const map = codec.decode(bytes); // new Map([["alice", 42]])
```

每个条目（键/值对）一个接一个地编码，先编码键，再编码值。 默认情况下，map 的大小以 `u32` 前缀的形式存储，然后再编码条目。

```ts twoslash
import { getMapCodec, getU8Codec, getUtf8Codec, fixCodecSize } from "@solana/kit";
// ---cut-before---
const codec = getMapCodec(fixCodecSize(getUtf8Codec(), 8), getU8Codec());
const myMap = new Map<string, number>();
myMap.set("alice", 42);
myMap.set("bob", 5);

codec.encode(myMap);
// 0x02000000616c6963650000002a626f62000000000005
//   |       |               | |               └-- 第 2 个条目值 (5).
//   |       |               | └-- 第 2 个条目键 ("bob").
//   |       |               └-- 第 1 个条目值 (42).
//   |       └-- 第 1 个条目键 ("alice").
//   └-- 4 字节前缀告诉我们要读取 2 个 map 条目。
```

但是，你可以使用 `size` 选项来配置此行为。 它可以是以下三种策略之一：

- `Codec<number>`：当提供数字 codec 时，该 codec 将用于编码和解码大小前缀。
- `number`：当提供数字时，该 codec 将期望 map 中具有固定数量的条目。 当尝试编码长度不同的 map 时，将引发错误。
- `"remainder"`：当字符串 `"remainder"` 作为大小传递时，该 codec 将使用剩余的字节来编码/解码其条目。 这意味着大小不会被存储或提前知道，而是简单地从缓冲区的其余部分推断出来。 例如，如果我们有一个 `u16` 数字 map 并剩下 10 个字节，我们就知道该 map 中有 5 个条目。

```ts twoslash
import { getNullableCodec, getU16Codec } from "@solana/kit";
// ---cut-before---
const codecWithZeroNoneValue = getNullableCodec(getU16Codec(), {
  noneValue: "zeroes", // 0x0000 means null.
  noneValue: "zeroes", // 0x0000 表示 null。
  prefix: null,
});
codecWithZeroNoneValue.encode(42); // 0x2a00
codecWithZeroNoneValue.encode(null); // 0x0000

const codecWithCustomNoneValue = getNullableCodec(getU16Codec(), {
  noneValue: new Uint8Array([255]), // 0xff means null.
  noneValue: new Uint8Array([255]), // 0xff 表示 null。
  prefix: null,
});
codecWithCustomNoneValue.encode(42); // 0x2a00
codecWithCustomNoneValue.encode(null); // 0xff
```

请注意，如果 `prefix` 设置为 `null` 并且没有提供 `noneValue`，则 codec 假定该项存在，当且仅当有一些剩余字节可用于解码时。这对于描述可能在缓冲区末尾有或没有附加数据的数据结构很有用。

```ts
const codec = getNullableCodec(getU16Codec(), { prefix: null });
codec.encode(42); // 0x2a00
codec.encode(null); // Encodes nothing.
codec.decode(new Uint8Array([42, 0])); // 42
codec.decode(new Uint8Array([])); // null
```

总而言之，以下是 `getNullableCodec` 函数的所有可能配置，以 `u16` codec 为例。

| `encode(42)` / `encode(null)` | No `noneValue` (default) | `noneValue: "zeroes"`       | Custom `noneValue` (`0xff`) |
| ----------------------------- | ------------------------ | --------------------------- | --------------------------- |
| `u8` prefix (default)         | `0x012a00` / `0x00`      | `0x012a00` / `0x000000`     | `0x012a00` / `0x00ff`       |
| Custom `prefix` (`u16`)       | `0x01002a00` / `0x0000`  | `0x01002a00` / `0x00000000` | `0x01002a00` / `0x0000ff`   |
| No `prefix`                   | `0x2a00` / `0x`          | `0x2a00` / `0x0000`         | `0x2a00` / `0xff`           |

请注意，您可能对可空 code 的 Rust 风格的替代版本感兴趣，该版本可用作 [getOptionCodec](#get-option-codec) 函数。

`getNullableEncoder` 和 `getNullableDecoder` 函数也可用。

### getOptionCodec [!toc] [#get-option-codec]

`getOptionCodec` 函数接受类型为 `T` 的 codec，并返回类型为 `Option<T>` 的 codec — 如 [`@solana/options`](https://github.com/anza-xyz/kit/tree/main/packages/options) 包中定义的那样。请注意，在编码时，也可以直接提供 `T` 或 `null` 作为输入，并将分别解释为 `Some(T)` 或 `None`。但是，在解码时，输出将始终为 `Option<T>` 类型。

默认情况下，它使用 `u8` 将该项是否存在存储为布尔前缀。

```ts twoslash
import { getOptionCodec, getU32Codec, addCodecSizePrefix, getUtf8Codec, some, none } from "@solana/kit";
// ---cut-before---
const stringCodec = addCodecSizePrefix(getUtf8Codec(), getU32Codec());

getOptionCodec(stringCodec).encode("Hi");
getOptionCodec(stringCodec).encode(some("Hi"));
// 0x01020000004869
//   | |       └-- utf8 string content ("Hi").
//   | |       └-- utf8 字符串内容 ("Hi")。
//   | └-- u32 string prefix (2 characters).
//   | └-- u32 字符串前缀（2 个字符）。
//   └-- 1-byte prefix (Some).
//   └-- 1 字节前缀 (Some)。

getOptionCodec(stringCodec).encode(null);
getOptionCodec(stringCodec).encode(none());
// 0x00
//   └-- 1-byte prefix (None).
//   └-- 1 字节前缀 (None)。
```

您可以提供一个数字 codec 作为 `getOptionCodec` 函数的 `prefix` 选项，以配置如何储存布尔前缀。

```ts twoslash
import { getOptionCodec, getU32Codec, addCodecSizePrefix, getUtf8Codec, some, none } from "@solana/kit";
const stringCodec = addCodecSizePrefix(getUtf8Codec(), getU32Codec());
// ---cut-before---
const u32OptionStringCodec = getOptionCodec(stringCodec, {
  prefix: getU32Codec(),
});

u32OptionStringCodec.encode(some("Hi"));
// 0x01000000020000004869
//   └------┘ 4-byte prefix (Some).
//   └------┘ 4 字节前缀 (Some)。

u32OptionStringCodec.encode(none());
// 0x00000000
//   └------┘ 4-byte prefix (None).
//   └------┘ 4 字节前缀 (None)。
```

此外，如果该项是 `FixedSizeCodec`，您可以将 `noneValue` 选项设置为 `"zeroes"`，以使返回的 Option codec 也成为 `FixedSizeCodec`。为此，它将用零填充 `None` 值，以匹配现有值的长度。

```ts twoslash
import { getOptionCodec, fixCodecSize, getUtf8Codec, some, none } from "@solana/kit";
// ---cut-before---
const codec = getOptionCodec(
  fixCodecSize(getUtf8Codec(), 8), // Only works with fixed-size items.
  { noneValue: "zeroes" },
);

codec.encode(some("Hi"));
// 0x014869000000000000
//   | └-- 8-byte utf8 string content ("Hi").
//   | └-- 8 字节 utf8 字符串内容 ("Hi")。
//   └-- 1-byte prefix (Some).
//   └-- 1 字节前缀 (Some)。

codec.encode(none());
// 0x000000000000000000
//   | └-- 8-byte of padding to make a fixed-size codec.
//   | └-- 8 字节填充以创建一个固定大小的 codec。
//   └-- 1-byte prefix (None).
//   └-- 1 字节前缀 (None)。
```

`noneValue` 选项也可以设置为显式字节数组，以用作 `None` 值的填充。请注意，在这种情况下，返回的 codec 将不是 `FixedSizeCodec`，因为表示 `None` 值的字节数组可以是任何长度。

```ts twoslash
import { getOptionCodec, getUtf8Codec, some, none } from "@solana/kit";
// ---cut-before---
const codec = getOptionCodec(getUtf8Codec(), {
  noneValue: new Uint8Array([255]), // 0xff means None.
  noneValue: new Uint8Array([255]), // 0xff 表示 None。
});

codec.encode(some("Hi"));
// 0x014869
//   | └-- 2-byte utf8 string content ("Hi").
//   | └-- 2 字节 utf8 字符串内容 ("Hi")。
//   └-- 1-byte prefix (Some).
//   └-- 1 字节前缀 (Some)。

codec.encode(none());
// 0x00ff
//   | └-- 1-byte representing None (0xff).
//   | └-- 1 字节表示 None (0xff)。
//   └-- 1-byte prefix (None).
//   └-- 1 字节前缀 (None)。
```

`getOptionCodec` 函数的 `prefix` 选项也可以设置为 `null`，这意味着不会使用前缀来确定该项是否存在。在这种情况下，codec 将依赖 `noneValue` 选项来确定该项是否为 `None`。

```ts twoslash
import { getOptionCodec, getU16Codec, some, none } from "@solana/kit";
// ---cut-before---
const codecWithZeroNoneValue = getOptionCodec(getU16Codec(), {
  noneValue: "zeroes", // 0x0000 means None.
  noneValue: "zeroes", // 0x0000 表示 None。
  prefix: null,
});
codecWithZeroNoneValue.encode(some(42)); // 0x2a00
codecWithZeroNoneValue.encode(none()); // 0x0000

const codecWithCustomNoneValue = getOptionCodec(getU16Codec(), {
  noneValue: new Uint8Array([255]), // 0xff means None.
  noneValue: new Uint8Array([255]), // 0xff 表示 None。
  prefix: null,
});
codecWithCustomNoneValue.encode(some(42)); // 0x2a00
codecWithCustomNoneValue.encode(none()); // 0xff
```

请注意，如果 `prefix` 设置为 `null` 并且没有提供 `noneValue`，则 codec 假定该项存在，当且仅当有一些剩余字节可用于解码时。这对于描述可能在缓冲区末尾有或没有附加数据的数据结构很有用。

```ts twoslash
import { getOptionCodec, getU16Codec, some, none } from "@solana/kit";
// ---cut-before---
const codec = getOptionCodec(getU16Codec(), { prefix: null });
codec.encode(some(42)); // 0x2a00
codec.encode(none()); // Encodes nothing.
codec.decode(new Uint8Array([42, 0])); // some(42)
codec.decode(new Uint8Array([])); // none()
```

总而言之，以下是 `getOptionCodec` 函数的所有可能配置，以 `u16` codec 为例。

| `encode(some(42))` / `encode(none())` | No `noneValue` (default) | `noneValue: "zeroes"`       | Custom `noneValue` (`0xff`) |
| ------------------------------------- | ------------------------ | --------------------------- | --------------------------- |
| `u8` prefix (default)                 | `0x012a00` / `0x00`      | `0x012a00` / `0x000000`     | `0x012a00` / `0x00ff`       |
| Custom `prefix` (`u16`)               | `0x01002a00` / `0x0000`  | `0x01002a00` / `0x00000000` | `0x01002a00` / `0x0000ff`   |
| No `prefix`                           | `0x2a00` / `0x`          | `0x2a00` / `0x0000`         | `0x2a00` / `0xff`           |

`getOptionEncoder` 和 `getOptionDecoder` 函数也可用。

### getSetCodec [!toc] [#get-set-codec]

`getSetCodec` 函数接受任何类型为 `T` 的 codec，并返回类型为 `Set<T>` 的 codec。

```ts twoslash
import { getSetCodec, getU8Codec } from "@solana/kit";
// ---cut-before---
const codec = getSetCodec(getU8Codec());
const bytes = codec.encode(new Set([1, 2, 3])); // 0x03000000010203
const value = codec.decode(bytes); // new Set([1, 2, 3])
```

默认情况下，集合的大小存储为 `u32` 前缀，然后再对项进行编码。

```ts twoslash
import { getSetCodec, getU8Codec } from "@solana/kit";
// ---cut-before---
getSetCodec(getU8Codec()).encode(new Set([1, 2, 3]));
// 0x03000000010203
//   |       └-- 3 items of 1 byte each.
//   |       └-- 每个 1 字节的 3 个项目。
//   └-- 4-byte prefix telling us to read 3 items.
//   └-- 4 字节前缀，告诉我们读取 3 个项目。
```

但是，您可以使用 `size` 选项来配置此行为。它可以是以下三种策略之一：

- `Codec<number>`：当提供数字 codec 时，该 codec 将用于编码和解码大小前缀。
- `number`：当提供数字时，该 codec 将期望集合中存在固定数量的项。尝试编码长度不同的集合时，将引发错误。
- `"remainder"`：当字符串 `"remainder"` 作为大小传递时，该 codec 将使用剩余的字节来编码/解码其项目。这意味着大小不会被存储或预先知道，而只是从缓冲区的其余部分推断出来。例如，如果我们有一个 `u16` 数字集合，并且剩余 10 个字节，我们知道此集合中有 5 个项。

```ts twoslash
import { getSetCodec, getU8Codec, getU16Codec } from "@solana/kit";
// ---cut-before---
getSetCodec(getU8Codec(), { size: getU16Codec() }).encode(new Set([1, 2, 3]));
// 0x0300010203
//   |   └-- 3 items of 1 byte each.
//   |   └-- 每个 1 字节的 3 个项目。
//   └-- 2-byte prefix telling us to read 3 items.
//   └-- 2 字节前缀，告诉我们读取 3 个项目。

getSetCodec(getU8Codec(), { size: 3 }).encode(new Set([1, 2, 3]));
// 0x010203
//   └-- 3 items of 1 byte each. There must always be 3 items in the set.
//   └-- 每个 1 字节的 3 个项目。集合中必须始终有 3 个项目。

getSetCodec(getU8Codec(), { size: "remainder" }).encode(new Set([1, 2, 3]));
// 0x010203
//   └-- 3 items of 1 byte each. The size is inferred from the remainder of the bytes.
//   └-- 每个 1 字节的 3 个项目。大小是从剩余字节中推断出来的。
```

`getSetEncoder` 和 `getSetDecoder` 函数也可用。

### getStructCodec [!toc] [#get-struct-codec]

`getStructCodec` 函数接受任意数量的字段 codec，并返回一个包含所有这些字段的对象的 codec。每个提供的字段都是一个数组，这样第一项是字段的名称，第二项是用于编码和解码该字段类型的 codec。

```ts twoslash
import { getStructCodec, getU8Codec, getUtf8Codec, addCodecSizePrefix, Codec, getU32Codec } from "@solana/kit";
// ---cut-before---
type Person = { name: string; age: number };
const personCodec: Codec<Person> = getStructCodec([
  ["name", addCodecSizePrefix(getUtf8Codec(), getU32Codec())],
  ["age", getU8Codec()],
]);

const bytes = personCodec.encode({ name: "alice", age: 42 });
// 0x05000000616c6963652a
//   |                 └-- Age field.
//   |                 └-- 年龄字段。
//   └-- Name field.
//   └-- 名字字段。

const person = personCodec.decode(bytes);
// { name: "alice", age: 42 }
```

`getStructEncoder` 和 `getStructDecoder` 函数也可用。

### getTupleCodec [!toc] [#get-tuple-codec]

`getTupleCodec` 函数接受任意数量的 codec — `T`、`U`、`V` 等 — 并返回一个类型为 `[T, U, V, …]` 的元组 codec，这样每个项都按照提供的 codec 的顺序排列。

```ts twoslash
import { getTupleCodec, getU8Codec, getU64Codec, addCodecSizePrefix, getUtf8Codec, getU32Codec } from "@solana/kit";
// ---cut-before---
const tupleCodec = getTupleCodec([addCodecSizePrefix(getUtf8Codec(), getU32Codec()), getU8Codec(), getU64Codec()]);

const bytes = tupleCodec.encode(["alice", 42, 123]);
// 0x05000000616c6963652a7b00000000000000
//   |                 | └-- 3rd item (123).
//   |                 | └-- 第 3 项 (123)。
//   |                 └-- 2nd item (42).
//   |                 └-- 第 2 项 (42)。
//   └-- 1st item ("alice").
//   └-- 第 1 项 ("alice")。

const value = tupleCodec.decode(bytes);
// ["alice", 42, 123]
```

`getTupleEncoder` 和 `getTupleDecoder` 函数也可用。

### getUnionCodec [!toc] [#get-union-codec]

`getUnionCodec` 是一个较低级别的 codec 辅助函数，可用于编码/解码任何 TypeScript 联合。

它接受以下参数：

- 一个 codec 数组，每个 codec 定义联合的一个变体。
- 一个 `getIndexFromValue` 函数，给定联合的一个值，返回应用于编码该值的 codec 的索引。
- 一个 `getIndexFromBytes` 函数，给定在给定偏移量处解码的字节数组，返回应用于解码下一个字节的 codec 的索引。

```ts twoslash
import { getUnionCodec, getU16Codec, getBooleanCodec, Codec } from "@solana/kit";
// ---cut-before---
const codec: Codec<number | boolean> = getUnionCodec(
  [getU16Codec(), getBooleanCodec()],
  (value) => (typeof value === "number" ? 0 : 1),
  (bytes, offset) => (bytes.slice(offset).length > 1 ? 0 : 1),
);

codec.encode(42); // 0x2a00
codec.encode(true); // 0x01
```

`getUnionEncoder` 和 `getUnionDecoder` 函数也可用。

### getUnitCodec [!toc] [#get-unit-codec]

`getUnitCodec` 函数返回一个 `Codec<void>`，它将 `undefined` 编码为空的 `Uint8Array`，并在解码时不消耗任何字节的情况下返回 `undefined`。这更像是一个低级 codec，可以由其他 codec 在内部使用。例如，这就是 [getDiscriminatedUnionCodec](#get-discriminated-union-codec) 描述空变体的 codec 的方式。

```ts twoslash
import { getUnitCodec } from "@solana/kit";
const anyBytes = null as unknown as Uint8Array;
// ---cut-before---
getUnitCodec().encode(undefined); // Empty Uint8Array
getUnitCodec().decode(anyBytes); // undefined
```

`getUnitEncoder` 和 `getUnitDecoder` 函数也可用。
